# QA-22: ContentAnalytics title/description length coerces present None to "None"

## Symptom
`ContentAnalytics.get_title_lengths()` and `get_description_lengths()` compute
`len(str(item.get("title", "")))` and `len(str(item.get("description", "")))`.
A *present* `None` value is stringified by `str()` to the literal `"None"`,
so a None title/description reports length 4 instead of 0. A *missing* key
correctly reports 0 (the default `""` is used). The two cases that both mean
"no text" disagree, corrupting `get_avg_title_length` / `get_avg_description_length`.

## Expected per docs
The docstrings say "Get lengths of all titles/descriptions". A missing or
None value means no text and must contribute length 0, not the 4-character
string `"None"`. The average must be computed over the true lengths.

## Repro
    python3 -c "
    from personal_index.content_analytics import ContentAnalytics
    a = ContentAnalytics()
    a.add_items([{'title': None}, {'title': 'ab'}])
    print(a.get_title_lengths())          # [4, 2]  (bug)  -> expected [0, 2]
    print(a.get_avg_title_length())       # 3.0    (bug)  -> expected 1.0
    b = ContentAnalytics()
    b.add_items([{'description': None}, {'description': 'ab'}])
    print(b.get_description_lengths())    # [4, 2]  (bug)  -> expected [0, 2]
    print(b.get_avg_description_length()) # 3.0    (bug)  -> expected 1.0
    "

## Observed output
`get_title_lengths()` -> `[4, 2]`; `get_avg_title_length()` -> `3.0`
`get_description_lengths()` -> `[4, 2]`; `get_avg_description_length()` -> `3.0`

## Expected output
`get_title_lengths()` -> `[0, 2]`; `get_avg_title_length()` -> `1.0`
`get_description_lengths()` -> `[0, 2]`; `get_avg_description_length()` -> `1.0`
