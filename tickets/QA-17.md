# QA-17: ContentPinner._load crashes with uncaught AttributeError on non-dict value

- Status: OPEN
- Component: `personal_index/content_pin.py`
- Issue: #1197

## Symptom

`ContentPinner.__init__` calls `_load`, which iterates over `data.items()` and
assumes each `item_data` is a dict, calling `item_data.get(...)`. If a valid
JSON file maps an id to a non-dict value (e.g. `{"a": "notadict"}`), the code
raises `AttributeError: 'str' object has no attribute 'get'` and crashes
construction.

The defensive-load contract in `_load` is to catch
`(json.JSONDecodeError, KeyError, TypeError)` and reset `self._pinned = {}`.
`AttributeError` is not in the tuple, so a malformed but valid-JSON file
crashes the pinner instead of being treated as empty.

## Repro

    python3 -c "import tempfile,os,json; from personal_index.content_pin import ContentPinner; d=tempfile.mkdtemp(); sp=os.path.join(d,'s.json'); open(sp,'w').write(json.dumps({'a':'notadict'})); ContentPinner(storage_path=sp)"

Expected per docs: construction succeeds and the pinner loads an empty set
(the file is malformed for the pinner's schema). Actual: `AttributeError`
raised during `__init__`.

Traceback:

    File ".../personal_index/content_pin.py", line 61, in _load
        pinned_at=item_data.get("pinned_at", ""),
    AttributeError: 'str' object has no attribute 'get'

## Deep test

`tests/deep/test_content_pin_adversarial.py::test_load_non_dict_value_yields_empty`
is xfail-strict with reason referencing QA-17.

## Notes

The fix is to broaden the defensive catch in `_load` (or validate `item_data`
is a dict before accessing `.get`). Validator does not fix; this is a QA
ticket for the implementer.
