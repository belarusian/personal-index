# QA-45: content_webhooks `payload_id` is not unique — `pl-{counter}-{timestamp}` collides when the counter only increments on `register_endpoint`, so `mark_delivered`/`mark_failed` act on the wrong payload

Status: CLAIMED 2026-09-15T00:00:00Z
Issue: #1618
Component: `personal_index/content_webhooks.py` (`WebhookManager._create_payload`, line 261; `_id_counter` increment only at `register_endpoint`, line 138)
Refs: `WebhookPayload.payload_id` docstring (line 76: "Unique identifier.")
Deep test: tests/deep/test_content_webhooks_adversarial.py (TestPayloadIdUniqueness::test_payload_ids_unique_across_dispatches, test_mark_delivered_does_not_orphan_twin — both xfail-strict)

## Symptom

`WebhookPayload.payload_id` is documented as a **"Unique identifier."** (line 76)
and is the key that `mark_delivered` (line 194) and `mark_failed` (line 209)
use to look a payload up in `self.pending`. But `_create_payload` builds it as

    payload_id=f"pl-{self._id_counter}-{int(time.time())}"   # line 261

and the `_id_counter` is incremented **only** in `register_endpoint`
(line 138), never in `_create_payload` or `dispatch_event`. So the counter is
constant across every dispatch to a given manager, and the only varying part of
the id is the wall-clock second. Two `dispatch_event` calls to the same
endpoint within the same second therefore produce **identical** `payload_id`s.

Consequence: `mark_delivered`/`mark_failed` iterate `self.pending` and match on
`payload.payload_id == payload_id`, so they operate on the **first** pending
payload with that id and leave the twin stranded. Delivering one of two
colliding payloads removes only one from `pending` and appends only one to
`delivered`; the second payload is orphaned under an id that no longer resolves
uniquely, and its delivery state can never be recorded correctly.

## Repro

    import time
    from personal_index.content_webhooks import WebhookManager, WebhookEventType
    time.time = lambda: 1000.0
    m = WebhookManager()
    m.register_endpoint("http://x",
        [WebhookEventType.CONTENT_ADDED, WebhookEventType.CONTENT_UPDATED])
    p1 = m.dispatch_event(WebhookEventType.CONTENT_ADDED, {"a": 1})
    p2 = m.dispatch_event(WebhookEventType.CONTENT_UPDATED, {"b": 2})
    print(p1[0].payload_id, p2[0].payload_id)   # pl-1-1000  pl-1-1000  (collision)
    print(len(m.pending))                        # 2
    m.mark_delivered(p1[0].payload_id)
    print(len(m.pending), len(m.delivered))      # 1  1  (twin orphaned in pending)

## Expected per docs

`WebhookPayload.payload_id` docstring (line 76) promises a **unique**
identifier, and `mark_delivered`/`mark_failed` are documented as operating on a
single payload by that id. Expected: every `dispatch_event` produces a
payload whose `payload_id` is distinct from every other payload's, so that
`mark_delivered`/`mark_failed` on one id affects exactly that one payload and
never orphans a sibling. Minimal fix: increment `_id_counter` in
`_create_payload` (or use a monotonic per-payload sequence) so the id is unique
regardless of wall-clock collisions.
