# QA-64: APIKeyStore.validate_key raises uncaught TypeError on a naive `expires_at`

- **Status:** CLAIMED 2026-09-21
- **Component:** `personal_index/auth/api_keys.py` (`APIKeyStore.validate_key`, line 104-110)
- **Kind:** contract violation (uncaught `TypeError` — naive-vs-aware datetime seam)
- **Deep test:** `tests/deep/test_api_keys_naive_expires_adversarial.py`

## Symptom

`validate_key` parses `api_key.expires_at` with `datetime.fromisoformat` and
compares `exp < datetime.now(timezone.utc)` (api_keys.py:106-107). The right-hand
`datetime.now(timezone.utc)` is UTC-**aware**. A *naive* ISO `expires_at` (no
`+00:00` / `Z` suffix) is a valid ISO format per the `create_key` docstring
("ISO format expiration datetime") and parses successfully, but `naive < aware`
raises `TypeError`. The `except` clause catches only `ValueError` (unparseable),
NOT `TypeError` (naive-vs-aware), so the exception propagates out of
`validate_key` instead of the key being treated as expired (aware past -> None)
or valid (aware future -> key).

This is the same naive-vs-aware datetime seam class as QA-62
(content_archive.archive_old, fixed in #1715) and QA-63 (sitemap.get_recent_entries
+ progress.elapsed_seconds, OPEN). The auth/api_keys.py:106 site is a NEW,
previously-unfiled member of that class.

## Exact repro

    from personal_index.auth.api_keys import APIKeyStore
    store = APIKeyStore()
    raw, key = store.create_key(owner='u', expires_at='2020-01-01T00:00:00')
    store.validate_key(raw)

## Expected per docs

`create_key` documents `expires_at` as "ISO format expiration datetime" — a naive
ISO string is a valid ISO format. `validate_key` should treat a naive `expires_at`
the same way it treats an aware one: normalize naive -> UTC (e.g.
`exp.replace(tzinfo=timezone.utc)` when `exp.tzinfo is None`) before comparing,
so a naive past expiration returns `None` (expired) and a naive future expiration
returns the key. The `except` clause should also catch `TypeError` as a defensive
guard.

## Asymmetry (same method, same call, pre-existing key)

    naive past   -> RAISES TypeError (defect)
    aware past   -> None (expired, correct)
    naive future -> RAISES TypeError (defect)
    aware future -> key (valid, correct)
    no expires_at-> key (valid, correct)
    unparseable  -> key (ValueError swallowed, correct)

## Deep test

`tests/deep/test_api_keys_naive_expires_adversarial.py` — 2 xfail-strict pins
documenting the defect (naive past / naive future) + 4 armor pins pinning the
already-correct aware / no-expiration / unparseable paths.

## Fix direction (implementer-owned, NOT validator)

In `validate_key`, after `exp = datetime.fromisoformat(api_key.expires_at)`,
normalize a naive `exp` to UTC (`if exp.tzinfo is None: exp = exp.replace(tzinfo=timezone.utc)`)
before the comparison, and broaden the `except` to `(ValueError, TypeError)`.
