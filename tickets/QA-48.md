# QA-48: content_exporter `ContentExporter` — two contract violations: (1) RSS `<guid>` is double-escaped when an item has no `id` but a `link` containing an XML-special char; (2) an explicit `None` field value crashes HTML/Markdown/RSS export with `AttributeError`

Status: CLOSED (validator cycle 320 @ main 396eea7: re-ran deep tests green on main; issue closed; primary defect confirmed fixed)
Issue: #1628
Component: `personal_index/content_exporter.py` (`ContentExporter._rss_item` line 188 — `guid = xml_escape(item.get("id", link))` where `link` is already `xml_escape`d at line 190; and `_html_item`/`_md_item`/`_rss_item` call `html.escape`/`_md_escape`/`xml_escape` on `item.get("title", "Untitled")` etc. without guarding against an explicit `None` value)
Refs: `ContentExporter.export` docstring ("every user-supplied field (title, description, tags, link, and the document title) is escaped with html.escape"; "RSS: title, description, link, and guid are escaped with xml.sax.saxutils.escape"); the per-format escaping contract promises well-formed output for arbitrary input
Deep test: tests/deep/test_content_exporter_adversarial.py (TestRssEscaping::test_rss_guid_fallback_single_escaped and TestEmptyAndMalformedItems::test_item_none_values — both xfail-strict)

## Symptom

Two distinct contract violations surfaced in the first deep-probe of
`ContentExporter` (232 lines, never previously probed):

### Defect 1 — RSS `<guid>` double-escape (no `id`, `link` has `&`)

`_rss_item` computes:

    link = xml_escape(item.get("link", self.base_url))   # escaped ONCE
    ...
    guid = xml_escape(item.get("id", link))              # escaped AGAIN when no id

When an item has no `id` field, the guid falls back to the ALREADY-escaped
`link` value, then `xml_escape` is applied a second time. So a link of `a&b`
becomes `a&amp;b` (first escape) and then `a&amp;amp;b` (second escape). An
RSS reader would render the guid as `a&amp;b` instead of `a&b`. When an `id`
IS present the guid is single-escaped correctly (`x&y` -> `x&amp;y`), so the
bug only fires on the id-less fallback path.

### Defect 2 — explicit `None` field value crashes HTML/Markdown/RSS export

The `export` docstring promises "every user-supplied field ... is escaped with
html.escape" and that the output is "well-formed for arbitrary input". But
`item.get("title", "Untitled")` returns `None` (not the default `"Untitled"`)
when the key is present with an explicit `None` value. `html.escape(None)`,
`_md_escape(None)`, and `xml_escape(None)` all call `.replace` on the value and
raise `AttributeError: 'NoneType' object has no attribute 'replace'`. So an
item with `title=None` (or `description=None`, `link=None`) crashes HTML,
Markdown, and RSS export. JSON is unaffected (json.dumps serializes None as
null). A MISSING key works fine (the default is used); only an explicit `None`
value crashes.

## Repro

    from personal_index.content_exporter import ContentExporter
    e = ContentExporter()

    # Defect 1: RSS guid double-escape (no id, link has &)
    import re
    rss = e.export([{"title": "T", "description": "D", "link": "a&b"}], "rss")
    print(re.search(r"<guid>(.*?)</guid>", rss).group(1))
    # -> 'a&amp;amp;b'   (expected 'a&amp;b')

    # Defect 2: explicit None field value crashes HTML export
    e.export([{"id": "x", "title": None, "description": "D", "link": "", "tags": []}], "html")
    # -> AttributeError: 'NoneType' object has no attribute 'replace'
    # (same crash for "markdown" and "rss")

## Expected per docs

- Defect 1: the RSS `<guid>` should be single-escaped. Minimal fix: compute the
  raw id/link first, then escape once for the guid — e.g.
  `guid = xml_escape(item.get("id") or item.get("link", self.base_url))` (escape
  the raw value, not the already-escaped `link` local).
- Defect 2: an explicit `None` field value should be treated like a missing
  field (use the default) rather than crashing. Minimal fix: guard each field
  read, e.g. `title = item.get("title") or "Untitled"` (or coalesce `None` to
  the default before calling the escape helper), so the documented "well-formed
  for arbitrary input" contract holds for `None` values as well as missing keys.
