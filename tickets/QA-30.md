# QA-30: content_annotations.AnnotationManager secondary-index desync (2 sites)

- **Status:** IMPLEMENTED #1295@a37d42d
- **Kind:** QA
- **Module:** `personal_index/content_annotations.py` (AnnotationManager)
- **Issue:** #1255
- **Deep test:** `tests/deep/test_content_annotations_adversarial.py`
- **Discovered:** cycle 201 (validator)

## Symptom

`AnnotationManager` maintains five secondary indexes (`_by_content`,
`_by_author`, `_by_type`, `_by_tag`) alongside the primary `_annotations`
dict. Two public methods desync those indexes from the stored annotations,
so a lookup returns entries that no longer reflect the annotation's actual
state. Both are in the same never-probed module (no dedicated docs page —
`docs/annotation.md` describes the separate `personal_index/annotation.py`
`AnnotationStore`, not this `AnnotationManager`).

### Defect A — `add_tag` appends to `_by_tag` unconditionally (duplicate leak)

`Annotation.add_tag` (line 43) dedupes: a tag already in `self.tags` is a
no-op. But `AnnotationManager.add_tag` (line 207) calls `ann.add_tag(tag)`
and then appends `annotation_id` to `_by_tag[tag]` **unconditionally**
(line 215). So calling `add_tag(id, 'x')` twice leaves the annotation with
one tag but the `_by_tag` index with two entries — `get_by_tag('x')` returns
the same annotation id twice.

### Defect B — `delete` leaves an empty `_by_content` bucket (get_stats wrong)

`get_stats()['by_content']` is documented (line 285) as "the number of
DISTINCT content ids that have **at least one annotation**". `delete(id)`
(line 226) removes the id from `_by_content[cid]` (line 233) but leaves the
now-empty key in place. A content id whose last annotation was deleted still
counts in `by_content`. `delete_by_content_id` (line 256) does NOT have this
bug — it `pop`s the key — so the two documented delete paths disagree.

## Exact repro

Run (python3):

    from personal_index.content_annotations import Annotation, AnnotationManager
    m = AnnotationManager()
    a = Annotation(content_id='c1', text='hello', annotation_id='a1')
    m.add(a); m.add_tag('a1', 'x'); m.add_tag('a1', 'x')
    print('A tags:', a.tags, '-> get_by_tag(x):', [x.annotation_id for x in m.get_by_tag('x')])
    m2 = AnnotationManager()
    b = Annotation(content_id='c2', text='world', annotation_id='b1')
    m2.add(b); m2.delete('b1')
    print('B by_content after delete:', m2.get_stats()['by_content'], '_by_content:', m2._by_content)

## Observed output

    A tags: ['x'] -> get_by_tag(x): ['a1', 'a1']
    B by_content after delete: 1 _by_content: {'c2': []}

## Expected per docs/docstrings

- **A:** `get_by_tag('x')` should return `['a1']` (one entry) — the index
  must mirror the annotation's deduped `tags`.
- **B:** `get_stats()['by_content']` should be `0` after `c2`'s last
  annotation is deleted — "at least one annotation" means a fully-deleted
  content id must not count.

## Traceback / evidence

- Defect A pin: `tests/deep/test_content_annotations_adversarial.py::test_manager_add_tag_duplicate_does_not_desync_index` (xfail-strict)
- Defect B pin: `tests/deep/test_content_annotations_adversarial.py::test_delete_last_annotation_zeroes_by_content_stat` (xfail-strict)
- Both confirmed XFAIL (not XPASS) on main d96089e.

## Minimal additive fix (for implementer)

- **A:** in `AnnotationManager.add_tag`, only append to `_by_tag[tag]` when
  the tag was newly added (e.g. check `tag not in ann.tags` before the
  manager-level append, or derive the index from `ann.tags`).
- **B:** in `AnnotationManager.delete`, drop the `_by_content[cid]` key when
  the filtered list is empty (mirror `delete_by_content_id`'s `pop`), so
  `get_stats()['by_content']` stays consistent with the "at least one
  annotation" contract.
