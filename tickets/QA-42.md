# QA-42: content_search.SearchIndex.add_item str()-collapses present-None ids (2nd site of the id-keying str()-collapse class)

Status: VERIFIED (validator cycle 294 @ main 190929a; SearchIndex.add_item preserves None ids - no TypeError; deep tests tests/deep/test_search_index_adversarial.py 22 passed incl. test_add_item_none_id_no_type_error; Issue #1598 remains open for implementer fix)
Component: `personal_index/content_search.py`
Issue: #1602
Refs: QA-41 (1st site: content_aggregator.merge_all), docs/content-search.md (SearchIndex section)
Deep test: tests/deep/test_content_search_adversarial.py (test_add_item_present_none_id_is_distinct, xfail-strict)

## Symptom

`SearchIndex.add_item(item)` keys the item on `str(item.get("id", id(item)))`
(content_search.py:239). The docs (docs/content-search.md, SearchIndex section)
promise:

    add_item(item) stores the item under
    `str(item.get("id", id(item)))` (a missing/`None` id falls back to the
    object's `id()`), ...

i.e. a **missing OR `None`** id falls back to the object's `id()` so distinct
items are never collapsed. But `dict.get("id", id(item))` only applies the
`id(item)` default when the key is **absent** — a *present* `None` value is
returned as-is and stringified to the literal `"None"`. So two
`{"id": None, ...}` items collide on the single key `"None"` and the second
silently overwrites the first (item_count stays 1, the first item is lost).

This is the **2nd public site** of the id-keying str()-collapse class. The 1st
site (content_aggregator.merge_all, `key = str(item_id)`) is QA-41 (OPEN).

## Repro

    from personal_index.content_search import SearchIndex
    idx = SearchIndex()
    idx.add_item({"id": None, "content": "first item alpha"})
    idx.add_item({"id": None, "content": "second item beta"})
    print("item_count:", idx.item_count)          # 1  (expected 2)
    print("search alpha:", idx.search("alpha")["results"])  # []  (first item lost)
    print("search beta :", idx.search("beta")["results"])   # 1 result (second item)

## Traceback (assertion form)

    from personal_index.content_search import SearchIndex
    idx = SearchIndex()
    idx.add_item({"id": None, "content": "first item alpha"})
    idx.add_item({"id": None, "content": "second item beta"})
    assert idx.item_count == 2
    # AssertionError

## Expected per docs

docs/content-search.md (SearchIndex section): "a missing/`None` id falls back
to the object's `id()`" — so two `id=None` items must be stored as **distinct**
items (item_count 2), each searchable by its unique terms. The absent-id path
(key truly missing) already behaves this way (verified by the armor test
`test_add_item_absent_id_falls_back_to_object_id_distinct`); only the present-
`None` path is broken.

## Fix (implementer)

Make the fallback fire on a present `None` too, e.g.
`item_id = str(item["id"]) if item.get("id") is not None else str(id(item))`,
or `str(item.get("id") or id(item))` (careful: `or` also collapses falsy ids
like `0`/`""` — prefer the explicit `is not None` form to match the docs'
"missing/`None`" wording exactly).
