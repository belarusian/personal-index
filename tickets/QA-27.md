# QA-27: negative-slice "top N" leak — five public sites return the wrong slice for `N < 0`

- Status: IMPLEMENTED #1289@f673ba0
- Kind: QA
- Component: `personal_index/url_history.py` (`URLHistory.get_visits`),
  `personal_index/performance_monitor.py` (`PerformanceMonitor.get_recent_samples`),
  `personal_index/content_notifications.py` (`NotificationManager.get_recent`),
  `personal_index/analytics.py` (`AnalyticsTracker.get_search_events`,
  `AnalyticsTracker.get_crawl_events`)
- Class home: ARCH-17 (issue #1049) — the negative-slice "top N / limit / count"
  truncation class (`N < 0 -> []`). This ticket covers the FIVE remaining
  unguarded public sites NOT in ARCH-17's original 5-site table.
- Issue: #1244
- Deep test: `tests/deep/test_url_history_adversarial.py`
  (6 xfail-strict defect pins in `TestNegativeSliceClassSweep` + 26 clean armor tests)

## Symptom

Five public entry points slice with an unguarded `[-N:]` (or `[:N]`) where `N`
is a caller-supplied `limit`/`count`. For `N < 0` they return the WRONG slice
instead of `[]`:

- `get_visits(limit=-1)` on 5 visits returns **4** visits (`results[-(-1):]` ==
  `results[1:]`, dropping the first entry) instead of the single most recent.
- `get_visits(limit=-2)` returns **3** instead of 2.
- The same shape recurs in the four sibling sites below.

Every guarded sibling in the codebase (e.g. `content_annotations.get_recent`,
`progress.get_recent`, `content_collections.get_recent`, `search_suggestions`,
`content_linker/similarity`, `content_scoring.rank`, `search_index.search`,
`content_linker/linker.find_related`, `content_export_csv`) does
`if N <= 0: return []`. These five do not.

## Root cause

Each site computes `results[-limit:]` (or `[:limit]`) with no `limit < 0` guard.
A negative `limit` flips the slice: `[-(-1):]` == `[1:]` (drops the head) and
`[-(-5):]` == `[5:]` (empty by accident, not by contract). The contract —
"return the top N most recent, `[]` when `N < 0`" — is violated.

## Exact repro

    python3 -c "from personal_index.url_history import URLHistory;h=URLHistory();[h.record(f'http://ex.com/{i}') for i in range(5)];print(len(h.get_visits(limit=-1)),[v.url for v in h.get_visits(limit=-1)])"

Output: `4 ['http://ex.com/1', 'http://ex.com/2', 'http://ex.com/3', 'http://ex.com/4']`
(expected: `1 ['http://ex.com/4']`).

    python3 -c "from personal_index.url_history import URLHistory;h=URLHistory();[h.record(f'http://ex.com/{i}') for i in range(5)];print(len(h.get_visits(limit=-2)))"

Output: `3` (expected: `2`).

## Expected per docs

ARCH-17 (issue #1049) class contract: a "top N / limit / count" truncation must
guard `N < 0 -> []`. For any `N < 0`, each of the five sites must return `[]`
(or, for the "most recent N" semantics, the single most recent entry when
`N == -1` is NOT the contract — the contract is `N < 0 -> []`). The fix is to
add `if N <= 0: return []` (matching the guarded siblings) at each of the five
sites.
