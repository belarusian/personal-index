# QA-46: content_export_csv `CSVExporter.export` clamps a negative `limit` to 0 but applies NO floor clamp to `offset`, so a negative `offset` leaks Python negative-slice semantics (`offset=-1` returns the LAST row)

Status: OPEN
Issue: #1622
Component: `personal_index/content_export_csv.py` (`CSVExporter.export`, line 89 `filtered = self._apply_filter_sort(items, filter_fn, sort_key)[offset:]`; the `limit` clamp at lines 91-92 has no `offset` counterpart)
Refs: `docs/CONTRACTS.md` negative-slice rule (explicitly names "the offset form"); `docs/content_export_csv.md` export() behavior step 2 (offset slice) and step 3 (limit clamp)
Deep test: tests/deep/test_content_export_csv_adversarial.py (TestLimitOffsetGuards::test_negative_offset_clamped_to_zero — xfail-strict)

## Symptom

`CSVExporter.export` guards the `limit` bound but not the `offset` bound. The
method docstring and `docs/content_export_csv.md` state that a **negative limit
is clamped to 0** (no rows emitted, identical to `limit=0`), and the code does
exactly that (lines 91-92). But `offset` is sliced raw at line 89:

    filtered = self._apply_filter_sort(items, filter_fn, sort_key)[offset:]

with no `if offset < 0: offset = 0` guard. Python negative-slice semantics
therefore leak through: `offset=-1` yields `list[-1:]` (the **last** row),
`offset=-2` yields the **last two** rows, and so on. A caller passing a
negative offset (e.g. from an unvalidated CLI/HTTP param) silently gets a
shifted tail window instead of the documented empty/zero-bound result.

This is the one-sided-guard leak: the cap (`limit`) is present, the floor
(`offset`) is missing. It violates the binding negative-slice rule in
`docs/CONTRACTS.md`, which requires a non-positive caller-supplied bound to
yield the same empty result as the zero bound and explicitly names "the offset
form" (`list[offset:offset-1]` = a shifted window) as the leak to guard
against.

## Repro

    from personal_index.content_export_csv import CSVExporter
    e = CSVExporter()
    items = [{"id": "1", "title": "a"}, {"id": "2", "title": "b"}, {"id": "3", "title": "c"}]
    print(e.export(items, offset=-1))   # 'id,title\n3,c\n'  (LAST row, not all rows)
    print(e.export(items, offset=-2))   # 'id,title\n2,b\n3,c\n'  (last two rows)
    print(e.export(items, offset=0))    # 'id,title\n1,a\n2,b\n3,c\n'  (all rows)

## Expected per docs

`docs/CONTRACTS.md` (negative-slice rule, the single home for the
negative-slice-truncation class) requires that a non-positive caller-supplied
count/limit/top_n/n/count MUST guard `N <= 0 -> []` and that "a negative `N`
must NOT leak Python negative-slice semantics (`list[:-1]` = all-but-last, and
in the offset form `list[offset:offset-1]` = a shifted window)". The guard must
short-circuit BEFORE the slice. `docs/content_export_csv.md` documents the
`limit` clamp (step 3) but the `offset` slice (step 2) has no equivalent floor
guard. Expected: `export(items, offset=-1)` behaves identically to
`export(items, offset=0)` (all rows), and `offset=-2` likewise — a negative
offset must NOT return a shifted tail window. Minimal fix: add
`if offset < 0: offset = 0` before the `[offset:]` slice at line 89 (mirroring
the existing `limit` clamp at lines 91-92), and state the guard in the method
docstring.
