# QA-44: cli_export `--tag` filter is a silent no-op — `set[str] & set[Tag]` is always empty because `Tag.__eq__` rejects non-Tag

Status: CLAIMED 2026-09-19
Issue: #1615
Component: `personal_index/cli_export.py` (`_load_pages`, lines 79-86) + `personal_index/tags.py` (`Tag.__eq__`, lines 25-28)
Refs: docs/cli_export.md (filter contract), ARCH-98 (export_cmd wiring)
Deep test: tests/deep/test_cli_export_adversarial.py (TestLoadPages::test_tag_filter_intersection, test_tag_filter_multiple_tags_any_match, test_filter_order_query_then_tag_then_limit; TestExportCmdE2E::test_tag_filter_e2e)

## Symptom

The `export` command's `--tag`/`-t` filter **silently returns zero pages** for
every real tag, even when the page is tagged with exactly that tag. The filter
is a no-op: it never matches, so `personal-index export --tag python` exports
nothing (or, when combined with other filters, drops every page) instead of the
tagged subset.

Root cause: `_load_pages` builds `tag_set = set(tag)` — a `set[str]` — and
intersects it with `set(page_tags)`, where `page_tags` is the return of
`TagStore.get_tags_for_page(url)`, which returns a `list[Tag]` of **`Tag`
objects** (not strings). The intersection `tag_set & set(page_tags)` therefore
compares `str` members against `Tag` members. `Tag.__eq__` (tags.py:25-28) is:

    def __eq__(self, other):
        if isinstance(other, Tag):
            return self.name == other.name
        return False

so `Tag(name='python') == 'python'` is `False` (and `'python' == Tag(...)` is
`False` too). The two sets are disjoint by construction, the `&` is always
`set()`, the `if page_tags and tag_set & set(page_tags)` guard is always
falsy, and `filtered` stays empty.

The existing e2e test masks the bug: `tests/test_cli_export_e2e.py::
test_load_pages_with_mock_tag_filter` (lines 158-177) mocks
`get_tags_for_page` to return **strings** (`["tag-a"]`), so the intersection
`{"tag-a"} & {"tag-a"}` is non-empty and the test passes. Against the real
`TagStore` (which returns `Tag` objects) the same code path returns nothing.

## Repro

    from personal_index.index import SearchIndex
    from personal_index.tags import TagStore
    from personal_index.models import IndexedPage
    from personal_index.cli_export import _load_pages

    idx = SearchIndex()
    ts = TagStore()
    idx.add_page(IndexedPage(url="http://a.com", title="A", content="python tutorial"))
    ts.add_tag_to_page("http://a.com", "python")

    pages = _load_pages(idx, ts, query=None, tag=("python",), limit=0)
    print([p.url for p in pages])   # []  (expected ['http://a.com'])

    # the intersection that is supposed to match:
    print(set(["python"]) & set(ts.get_tags_for_page("http://a.com")))
    # set()  (Tag(name='python') == 'python' is False)

## Expected per docs

docs/cli_export.md (Public surface, `_load_pages` row + Invariants): "If
`tag`: keep pages whose `tag_store.get_tags_for_page(url)` intersects `set(tag)`."
The documented contract is that a page is kept when its tags **intersect** the
requested tag set. With a real `TagStore`, `get_tags_for_page` returns `Tag`
objects, so the intersection must compare tag *names* — i.e. the filter must
match a page tagged `python` when `--tag python` is given. Expected: the
`--tag` filter returns exactly the pages whose tag names intersect the requested
set (verified: with the fix, `tag=("python",)` -> `{'http://a.com','http://c.com'}`,
`tag=("tutorial","python")` -> `{'http://a.com','http://c.com'}`,
`query="python" + tag=("tutorial",) + limit=1` -> `['http://a.com']`).

## Fix (implementer)

Make the intersection compare tag names. Either (a) in `_load_pages`
(cli_export.py:83-84) compare against names —
`page_tag_names = {t.name if hasattr(t, "name") else str(t) for t in page_tags}`
and test `tag_set & page_tag_names` — or (b) make `Tag.__eq__` (tags.py:25-28)
compare by name against a `str` as well (`return self.name == other.name if
isinstance(other, Tag) else self.name == other`). Option (a) is the minimal,
localized fix that does not change `Tag`'s equality/hash semantics for other
callers. Then the 4 red deep tests in
tests/deep/test_cli_export_adversarial.py turn green (they are plain hard
assertions pinning the documented intersection contract, not xfail pins).
