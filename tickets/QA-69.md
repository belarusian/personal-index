# QA-69: RouteMatcher._matches crashes with TypeError when content['url'] is None

- **Status:** CLOSED (validator cycle 345 @ main be2e5dc; re-ran pinning deep tests tests/deep/test_content_router_adversarial.py green + fresh adversarial None/absent url with non-wildcard pattern -> None no TypeError; issue #1735 already CLOSED by implementer fix PR)
- **Component:**
  * `personal_index/content_router/route.py` (`RouteMatcher._matches`, line ~63: `route.pattern in url`)
- **Kind:** contract violation (uncaught `TypeError` on a `None` url value)
- **Issue:** #1735
- **Deep test:** `tests/deep/test_content_router_adversarial.py` (1 xfail-strict pin: `test_match_none_url_treated_as_empty`)

## Symptom

`RouteMatcher._matches` reads the url with:

    url = content.get("url", "")

and then does:

    pattern_matches = (
        route.pattern in url
        or route.pattern == content_type
        or route.pattern == "*"
    )

The `content.get("url", "")` guard only handles a MISSING `url` key (defaulting
to `""`). When the `url` key is PRESENT but its value is `None`, `url` is
`None`, and `route.pattern in url` raises:

    TypeError: argument of type 'NoneType' is not iterable

This escapes `match()` / `match_all()` / `ContentRouter.route()` uncaught. A
`None` url is a plausible input (a content item that has no url, e.g. a
type-only item serialized with an explicit `null`), and the wildcard route
(`pattern == "*"`) is documented to match ANY content — yet a `None` url makes
even the wildcard route crash instead of matching.

## Exact repro

    python3 -c "
    from personal_index.content_router.route import Route, RouteMatcher
    m = RouteMatcher()
    m.add_route(Route(name='all', pattern='*', handler=lambda c: c))
    m.match({'url': None, 'type': 'article'})
    "

## Expected per docs

The wildcard route (`pattern == "*"`) is documented to match any content. A
content item whose `url` is `None` (or whose `url` key is absent) should match
the wildcard route, not crash. The url read should be coerced to a string, e.g.
`url = content.get("url") or ""` (or `str(content.get("url") or "")`), so that
both a missing key and a `None` value fall back to `""` and the `in` / `==`
checks operate on a string.

## Asymmetry (same wildcard route, only the url value differs)

    url key absent  -> matches wildcard (correct)
    url = ""        -> matches wildcard (correct)
    url = "http://x"-> matches wildcard (correct)
    url = None      -> RAISES TypeError (defect)
