# QA-14: ContentCategorizer.categorize() crashes AttributeError on title=None / meta_description=None

Status: CLAIMED 2026-09-10 (cycle 231)
Priority: medium
Component: personal_index/content_categorizer.py
Filed: Cycle 175
Issue: #1180

## Summary

`ContentCategorizer.categorize(text, title="", url="", meta_description="")`
types both `title` and `meta_description` as `str` with a default of `""`,
and its docstring describes the guard path as "if ``text``, ``title`` and
``meta_description`` are all falsy, return ... unknown". Passing `None` for
either of those two parameters (a common caller mistake, and a value that is
itself falsy) does NOT take the guard path and does NOT degrade gracefully:
it crashes with an unhandled `AttributeError` from `_lowercase_signals`.

The falsy guard `if not text and not title and not meta_description` is
evaluated *before* lowercasing, so a `None` title with a truthy `text` skips
the guard and reaches `title.lower()` on line 453.

## Repro

    python3 -c "
    from personal_index.content_categorizer import ContentCategorizer
    c = ContentCategorizer()
    c.categorize(text='hello world', title=None, meta_description=None)
    "

## Expected per docs

- Signature: `def categorize(self, text: str, title: str = "", url: str = "",
  meta_description: str = "")`. Both `title` and `meta_description` are
  `str`-typed with a `""` default, so a `None` value is out-of-contract input
  that the falsy guard (`if not text and not title and not meta_description`)
  is positioned to absorb.
- Docstring guard path: "if ``text``, ``title`` and ``meta_description`` are
  all falsy, return `CategorizationResult(primary_topic='unknown', ...)`".
  `None` is falsy, so a caller passing `None` for the optional signals should
  either hit the guard (all-falsy) or degrade to the empty-string behaviour
  (treat `None` as `""`), not raise `AttributeError`.
