# QA-61 — URLHistory.load clears pre-existing history on malformed record (missing url / wrong-type url / non-dict record)

**Status:** CLAIMED 2026-09-21

## Symptom
`URLHistory.load` docstring (personal_index/url_history.py:158-170) and the ARCH-76 contract state:

> Returns 0 (leaving _history untouched) for a missing file, invalid JSON, a parsed value that is not a list, or a list containing a record that URLVisit.from_dict cannot construct (unexpected key, missing url, or a value of the wrong type).

The QA-38 fix (commit bb0b927) added a filter to reject records whose `url` is not a `str` plus a length-mismatch guard:

    self._history = [
        URLVisit.from_dict(d)
        for d in data
        if isinstance(d, dict) and isinstance(d.get("url"), str)
    ]
    ...
    if len(self._history) != len(data):
        self._history = []
        return 0

When a record is missing `url`, has a wrong-type `url`, or is not a dict, the filter drops it, the length-mismatch guard fires, and the code executes `self._history = []` — CLEARING any pre-existing history. The docstring requires the history to be LEFT UNTOUCHED.

## Repro command
    python3 -c "
    from personal_index.url_history import URLHistory
    import json, tempfile, os
    d = tempfile.mkdtemp()
    p = os.path.join(d, 'h.json')
    with open(p,'w') as f: json.dump([{'url':'http://good.com'},{'url':123}], f)
    h = URLHistory(); h.record('http://pre.com')
    print('before', len(h._history))
    n = h.load(p)
    print('load returned', n)
    print('after', len(h._history), [v.url for v in h._history])
    "

## Expected per docs
`load` returns 0 AND leaves _history untouched — pre-existing visits remain.

## Actual
`load` returns 0 but `h._history` is cleared to `[]` (len 0). The pre-existing visit is silently lost.

## Evidence
No exception; silent data loss. The repro above prints:
    before 1
    load returned 0
    after 0 []

Asymmetry (same module, same load call, pre-existing visit http://pre.com):
    unexpected_key   ret=0  after_len=1  urls=['http://pre.com']   (untouched — correct)
    missing_url      ret=0  after_len=0  urls=[]                   (CLEARED — defect)
    wrong_type_url   ret=0  after_len=0  urls=[]                   (CLEARED — defect)
    non_dict_rec     ret=0  after_len=0  urls=[]                   (CLEARED — defect)

The unexpected-key case correctly leaves _history untouched (it raises TypeError inside the comprehension, caught by `except TypeError: return 0` before _history is reassigned). The missing-url / wrong-type-url / non-dict cases go through the filter-drop path which reassigns `self._history = []`.

## Fix direction (implementer-owned, NOT validator)
On the filter-drop path, do NOT clear _history. Either (a) build the filtered list into a local and only assign to self._history when the full list is constructible (all-or-nothing without clearing), or (b) preserve the prior _history on the length-mismatch branch. The docstring contract is "untouched", so the minimal fix is to snapshot `prior = self._history` before the comprehension and restore it on the `len(...) != len(data)` branch.
