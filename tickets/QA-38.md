# QA-38: url_history `URLHistory.load` accepts a wrong-type `url` record (returns 1, counts it) and the stored non-string url then crashes `get_domain_stats` with `AttributeError`

## Symptom
`URLHistory.load` (personal_index/url_history.py:157-181) degrades gracefully
for a missing file, invalid JSON, a non-list, and a list whose records
`URLVisit.from_dict` cannot construct via an **unexpected key** or a **missing
`url`** (the ARCH-76 fix, commit 68f9aa0 / merged 4830dfe). But it does NOT
degrade for a record whose `url` field is the **wrong type** (e.g. an `int`):
the plain `@dataclass URLVisit` performs no type enforcement, so
`URLVisit.from_dict({"url": 123})` constructs fine, `load` returns **1** and
counts the record. The stored non-string url then crashes
`get_domain_stats` (line 133, `urlparse(v.url)`) with
`AttributeError: 'int' object has no attribute 'decode'`.

This violates the `load` docstring that ARCH-76 required the implementer to
write (url_history.py:158-166):

    Returns 0 (leaving _history untouched) for a missing file, invalid
    JSON (json.JSONDecodeError), a parsed value that is not a list, or a
    list containing a record that URLVisit.from_dict cannot construct
    (unexpected key, missing url, or a value of the wrong type).

The docstring explicitly lists "a value of the wrong type" as a 0-return case,
but the code returns 1 for `{"url": 123}`. The graceful-degradation goal of
ARCH-76 ("never raises on file contents") is also undermined downstream: a
file that `load` happily accepts produces a history that crashes
`get_domain_stats`.

This is PRE-EXISTING (the plain dataclass never enforced `url: str`), not
introduced by the ARCH-76 fix — but the ARCH-76 docstring now makes the
wrong-type case an explicit contract promise the code does not keep.

Repro (exact):

    python3 -c "
    from personal_index.url_history import URLHistory
    import tempfile, os, json
    d = tempfile.mkdtemp()
    p = os.path.join(d, 'wt.json')
    open(p, 'w').write(json.dumps([{'url': 123}]))
    h = URLHistory()
    print('load ->', h.load(p))          # 1  (docstring says 0)
    print('counted ->', len(h.get_visits()))  # 1
    h.get_domain_stats()                 # AttributeError: 'int' object has no attribute 'decode'
    "

## Why it is a real contract violation
- The `load` docstring (required by ARCH-76) lists "a value of the wrong type"
  as a 0-return case; the code returns 1 for `{"url": 123}`.
- The observable contract bullet 3 ("returns the number of visits actually
  loaded") is satisfied for the constructible record, but the docstring's
  wrong-type clause is not — the two statements in the same docstring
  disagree with the code.
- Downstream, the accepted non-string url crashes `get_domain_stats`, so a
  file `load` accepts yields a history that cannot be fully queried.

## Expected per docs
Either (a) `load` rejects a record whose `url` is not a `str` (returns 0,
matching the docstring's wrong-type clause), or (b) the docstring's wrong-type
clause is removed/clarified AND `get_domain_stats` (and any other consumer of
`v.url`) is made robust to a non-string url so loaded data never crashes.
The fix is the implementer's choice; the observable contract is "a file
`load` accepts yields a history whose query methods do not crash."
