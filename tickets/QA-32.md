# QA-32: bookmark_export inserts raw URL into OPML/HTML attributes, producing invalid output

- **Status:** CLAIMED 2026-09-12 (cycle 261)
- **Kind:** QA
- **Module:** `personal_index/bookmark_export.py` (BookmarkExporter.export_opml / export_html)
- **Issue:** #1259
- **Deep test:** `tests/deep/test_bookmark_export_adversarial.py`
- **Discovered:** cycle 203 (validator)

## Symptom

`BookmarkExporter.export_opml` builds each outline line as
`f'  <outline text="{display_title}" htmlUrl="{b.url}" type="bookmark"/>'`
where `display_title` is escaped via `_escape_xml` but **`b.url` is inserted
raw**. A URL containing `&` (an extremely common query string, e.g.
`https://example.com/search?q=hello&lang=en`), `<`, or `"` therefore produces
XML that is **not well-formed**, contradicting the docstring claim:

> "Produces a **valid OPML 2.0 document** with a head section containing
> metadata and a body section containing outline elements for each bookmark."

The same raw-URL insertion in `export_html`
(`f'<DT><A HREF="{b.url}" ADD_DATE="{now}">{display_title}</A>'`) breaks the
`HREF` attribute when the URL contains a double-quote, contradicting the
"standard Netscape bookmark file that can be imported into most browsers"
claim.

Affected characters in the URL:
- `&`  -> OPML: `not well-formed (invalid token)` (bare ampersand is not a valid XML entity start)
- `<`  -> OPML: `not well-formed (invalid token)` (starts a tag)
- `"`  -> OPML: `not well-formed`; HTML: terminates the `HREF` attribute early

## Exact repro

Run (python3):

    import xml.etree.ElementTree as ET
    from personal_index.bookmarks import Bookmark
    from personal_index.bookmark_export import BookmarkExporter
    b = Bookmark(url='https://example.com/search?q=hello&lang=en', title='T')
    out = BookmarkExporter([b]).export_opml()
    ET.fromstring(out)   # raises ParseError

## Expected per docs/docstrings

`export_opml` promises a **valid OPML 2.0 document**. The URL must be
XML-escaped (via the existing `_escape_xml`) before being placed in the
`htmlUrl` attribute, so that any legal URL — including ones with `&`, `<`,
`>`, `"`, `'` — yields well-formed XML. `export_html` must likewise escape the
URL for the `HREF` attribute (via `_escape_html`) so a `"` in the URL does not
break the attribute.

- Defect pins (xfail-strict):

- Confirmed XFAIL (not XPASS) on main 932c560.

## Minimal additive fix (for implementer)

In `export_opml`, escape the URL before interpolation, e.g.
`url = self._escape_xml(b.url)` and use `htmlUrl="{url}"`. In `export_html`,
escape the URL for the attribute, e.g. `href = self._escape_html(b.url)` and
use `HREF="{href}"`. (Note: `_escape_html` does not escape `'`, which is fine
for a double-quoted HTML attribute; `_escape_xml` escapes all five XML
specials.)
