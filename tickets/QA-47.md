# QA-47: content_scoring `ContentScorer._score_authority` docstring promises the result is "capped at 1.0", but the `min(1.0, ...)` cap is applied ONLY in the `is_verified_source` branch — a non-verified `domain_authority` outside [0.0, 1.0] is returned unchanged, violating the documented 0.0-1.0 factor range

Status: CLAIMED 2026-09-20
Issue: #1626
Component: `personal_index/content_scoring.py` (`ContentScorer._score_authority`, line 337; the `min(1.0, score + 0.1)` cap at line 348 is inside the `if is_verified_source:` block, so the non-verified path returns `round(domain_authority, 4)` with no floor or ceiling)
Refs: `_score_authority` docstring ("capped at 1.0"); the six factor helpers are documented as 0.0-1.0 scores (e.g. `_score_engagement` "0.0-1.0", `_score_quality` "0.0-1.0"); `ContentScore.total` is documented as a 0.0-1.0 composite
Deep test: tests/deep/test_content_scoring_adversarial.py (TestScoreAuthority::test_non_verified_over_cap_clamped_to_one and test_non_verified_negative_clamped_to_zero — both xfail-strict)

## Symptom

`_score_authority`'s docstring states the result is "capped at 1.0 and rounded
to 4 places". But the only cap in the body is:

    score = domain_authority
    if is_verified_source:
        score = min(1.0, score + 0.1)
    return round(score, 4)

The `min(1.0, ...)` guard lives INSIDE the verified branch. On the non-verified
path the raw `domain_authority` is returned unchanged. So a non-verified
`domain_authority > 1.0` (e.g. 1.5) is returned as 1.5, and a negative one
(e.g. -0.5) is returned as -0.5 — both outside the documented 0.0-1.0 factor
range. The verified branch IS capped (1.5 -> 1.0), so the guard is one-sided:
cap present for verified sources, absent for non-verified. This lets an
out-of-range authority value flow into `ContentScore.total` and break the
composite's documented 0.0-1.0 range.

## Repro

    from personal_index.content_scoring import ContentScorer
    s = ContentScorer()
    print(s._score_authority(1.5, False))   # 1.5   (docstring says capped at 1.0)
    print(s._score_authority(-0.5, False))  # -0.5  (outside the 0.0 floor)
    print(s._score_authority(1.5, True))    # 1.0   (verified branch IS capped)

## Traceback (assertion form)

    tests/deep/test_content_scoring_adversarial.py::TestScoreAuthority::test_non_verified_over_cap_clamped_to_one
      assert scorer._score_authority(1.5, False) == 1.0
      -> AssertionError: assert 1.5 == 1.0   (non-verified over-cap value not clamped)

## Expected per docs

The docstring promises the factor is "capped at 1.0" and the sibling factor
helpers are documented as 0.0-1.0 scores. Expected: `_score_authority` clamps
its result to [0.0, 1.0] on BOTH branches (e.g. `return round(max(0.0, min(1.0, score)), 4)` after the optional +0.1 bonus), so a non-verified `domain_authority` of 1.5 -> 1.0 and -0.5 -> 0.0. Minimal fix: move the cap/floor outside the `if is_verified_source:` block so it applies to the returned value unconditionally.
