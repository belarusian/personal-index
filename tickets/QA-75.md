# QA-75: BackupManager.cleanup_old_backups raises TypeError on a backup with a naive timestamp (imported from a file with a naive ISO timestamp)

- **Status:** OPEN
- **Kind:** QA (validator-authored defect)
- **File:** personal_index/content_backup/backup_manager.py
- **Function:** BackupManager.cleanup_old_backups
- **Issue:** #1780
- **Deep test:** tests/deep/test_content_backup_adversarial.py::TestBackupManager::test_cleanup_naive_timestamp_no_typeerror (xfail-strict pin documenting this defect)

## Symptom

`cleanup_old_backups` builds an aware UTC cutoff (`datetime.now(timezone.utc) -
older_than`) and then compares each backup's **raw** timestamp against it:

    to_remove = [
        b.backup_id
        for b in self.store.list_backups()
        if b.timestamp < cutoff          # backup_manager.py:131
    ]

`b.timestamp` is NOT normalized here. The package already ships a
`_normalize_tz` helper (backup_store.py:12) whose documented purpose is to make
a naive timestamp UTC-aware so "a naive timestamp and an aware timestamp never
raise `TypeError: can't compare offset-naive and offset-aware datetimes` at the
sort/min". That helper is applied in `list_backups` (line 111) and
`_evict_oldest` (line 140) but **not** in `cleanup_old_backups`.

A backup imported from a JSON file with a naive ISO timestamp
(`"2020-01-01T00:00:00"`, no offset) gets a naive `datetime` from
`datetime.fromisoformat` (backup_store.py:197). Such a backup is a fully valid
store entry (it sorts fine in `list_backups`/`get_latest`), but calling
`cleanup_old_backups` on a store containing it raises `TypeError` instead of
returning the count of removed backups.

## Exact repro

    python3 -c "
    import json, tempfile, os
    from datetime import timedelta
    from personal_index.content_backup.backup_store import BackupStore
    from personal_index.content_backup.backup_manager import BackupManager
    d = tempfile.mkdtemp(); fp = os.path.join(d, 'b.json')
    json.dump({'backup_id':'b1','timestamp':'2020-01-01T00:00:00','item_count':1,'items':[{'id':'x'}],'metadata':{}}, open(fp,'w'))
    store = BackupStore(); store.import_from_file(fp)
    print(BackupManager(store=store).cleanup_old_backups(older_than=timedelta(days=30)))
    "

## Observed output

    Traceback (most recent call last):
      File "<stdin>", line 8, in <module>
      ...

    TypeError: can't compare offset-naive and offset-aware datetimes

## Expected per docs

`cleanup_old_backups` should normalize each backup's timestamp with
`_normalize_tz` before comparing it to the aware cutoff (mirroring
`list_backups`/`_evict_oldest`), so a store holding a naive-timestamp backup
returns the integer count of removed backups instead of raising. The
`_normalize_tz` docstring explicitly promises that naive/aware timestamps never
raise at the comparison.
