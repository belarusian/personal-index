# QA-11: domains.DomainManager._load crashes (TypeError) on structurally-malformed rules file

## Symptom
`DomainManager._load` only catches `(json.JSONDecodeError, KeyError)`. A rules
file whose top-level is a dict but whose rule VALUE is not a mapping (a plain
string) — or a dict with an unexpected key — raises `TypeError` from
`DomainRule.from_dict`, which propagates out of `__post_init__` and fails the
whole manager construction instead of degrading gracefully:

    self._rules = {
        d: DomainRule.from_dict(r) for d, r in data.items()
    }
    ...
    except (json.JSONDecodeError, KeyError):
        self._rules = {}

The except clause does not cover the `TypeError` that `cls(**data)` raises when
`data` is not a mapping or carries an unknown keyword.

## Affected site
| module | function | line | idiom |
|--------|----------|------|-------|
| domains.py | `DomainManager._load` | ~69-75 | `DomainRule.from_dict(r)` in dictcomp; `except (json.JSONDecodeError, KeyError)` |
| domains.py | `DomainRule.from_dict` | ~44 | `return cls(**data)` (no key filtering) |

## Exact repro
    python3 -c "
    import json, tempfile, os
    from personal_index.domains import DomainManager
    d = tempfile.mkdtemp(); rf = os.path.join(d, 'rules.json')
    with open(rf, 'w') as f: json.dump({'example.com': 'notadict'}, f)
    m = DomainManager(rules_file=rf)
    "

## Observed output (traceback)
    File ".../personal_index/domains.py", line 69, in _load
        self._rules = {
    File ".../personal_index/domains.py", line 70, in <dictcomp>
        d: DomainRule.from_dict(r) for d, r in data.items()
    File ".../personal_index/domains.py", line 44, in from_dict
        return cls(**data)
    TypeError: personal_index.domains.DomainRule() argument after ** must be a mapping, not str

A second variant (rule dict with an unexpected key) raises:
    TypeError: DomainRule.__init__() got an unexpected keyword argument 'future_field'

## Expected per docs/contract
The `try/except` in `_load` establishes a graceful-degradation intent: corrupt
JSON (`json.JSONDecodeError`) and a non-dict top-level (the `isinstance(data,
dict)` guard) both degrade to an empty rule set. A structurally-malformed rule
value should degrade the same way (skip the bad entry, or reset to empty rules),
not crash construction. `from_dict` should tolerate unknown keys (forward
compatibility) rather than raising on them.
