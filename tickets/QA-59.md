# QA-59: SessionManager.load_session raises AttributeError when the persisted "stats" field is a non-dict value

- **Component:** `personal_index/session.py` (`SessionManager.load_session`, lines ~330-336)
- **Status:** OPEN
- **Issue:** #1695
- **Deep test:** `tests/deep/test_session_adversarial.py::TestLoadSessionStatsShape` (3 xfail-strict pins: `test_stats_as_list_degrades_to_empty`, `test_stats_as_number_degrades_to_empty`, `test_stats_as_null_degrades_to_empty`)
- **Related:** ARCH-63 (docs/CONTRACTS.md "Defensive-load guard (binding)"); the defensive-load-crash class (QA-20 sweep, QA-11, QA-17)

## Symptom
`SessionManager.load_session` reads the persisted stats with
`stats_data = data.get("stats", {})` and then immediately calls
`stats_data.get("urls_crawled", 0)` (and the four sibling counters) on it.
When the persisted `stats` field is a NON-DICT value (a list, a number, a
string, or `null`), `.get` raises `AttributeError` out of `load_session`
instead of degrading to the empty stats state.

This violates the ARCH-63 defensive-load guard: a well-formed-but-wrong-shape
value (a value that is not a mapping) MUST yield the same empty state as a
missing file and MUST NOT raise out of construction. The missing-`stats` case
(`data.get("stats", {})` -> `{}`) is already safe; only the present-but-
wrong-shape case crashes.

## Repro
    import json, tempfile, os
    from personal_index.session import SessionManager
    d = tempfile.mkdtemp()
    p = os.path.join(d, "s.json")
    with open(p, "w") as f:
        json.dump({"session_id": "x", "status": "active", "stats": [1, 2, 3]}, f)
    SessionManager().load_session(p)
    # -> AttributeError: 'list' object has no attribute 'get'

Same crash for `"stats": 42` (int), `"stats": "oops"` (str), `"stats": null`.

## Traceback
    File "personal_index/session.py", line 332, in load_session
        urls_crawled=stats_data.get("urls_crawled", 0),
    AttributeError: 'list' object has no attribute 'get'

## Expected per docs
Per docs/CONTRACTS.md "Defensive-load guard (binding)" (ARCH-63): a non-mapping
`stats` value MUST degrade to the empty stats state (all counters 0), exactly
like a missing `stats` key, and MUST NOT raise. The fix is to guard the shape,
e.g. `stats_data = data.get("stats") or {}` plus
`if not isinstance(stats_data, dict): stats_data = {}`, so a wrong-shape value
yields the empty state.

## Deep test
`tests/deep/test_session_adversarial.py::TestLoadSessionStatsShape` pins the
defect xfail-strict (3 pins) and pins the safe cases (missing stats, empty
dict) as clean armor. When the implementer adds the shape guard, the 3 pins
XPASS and xfail-strict turns them red, alerting the validator to re-verify and
close QA-59.
