# QA-28: negative-slice "top N" leak — two more public sites return the wrong slice for `N < 0`

- Status: OPEN
- Kind: QA
- Component: `personal_index/migrations/runner.py` (`MigrationRunner.rollback`),
  `personal_index/backup.py` (`BackupManager.cleanup_old_backups`)
- Class home: ARCH-17 (issue #1049) — the negative-slice "top N / limit / count"
  truncation class (`N < 0 -> []`). This ticket covers TWO remaining unguarded
  public sites NOT in ARCH-17's original 5-site table and NOT in QA-27's five.
- Issue: #1246
- Deep test: `tests/deep/test_negslice_sweep3_adversarial.py`
  (4 xfail-strict defect pins + 7 clean armor tests)

## Symptom

Two public entry points slice with an unguarded `[:N]` / `[:-N]` where `N` is a
caller-supplied `steps` / `keep`. For `N < 0` they return the WRONG slice
instead of `[]`:

- `MigrationRunner.rollback(steps=-1)` with 3 applied migrations rolls back
  **2** (all-but-last) instead of **0**. `list(reversed(applied))[:-1]` drops
  the last element of the reversed list, i.e. the OLDEST migration, and rolls
  back the rest.
- `BackupManager.cleanup_old_backups(keep=-1)` with 5 backups **deletes 1**
  instead of **0**. `backups[:-(-1)]` == `backups[1:]` deletes every backup
  except the most recent.

Every guarded sibling in the codebase (e.g. `content_annotations.get_recent`,
`progress.get_recent`, `content_collections.get_recent`, `search_suggestions`,
`content_linker/similarity`, `content_scoring.rank`, `search_index.search`,
`content_linker/linker.find_related`, `content_export_csv`, `cli_top.top_pages`,
`content_digest.generate`) does `if N <= 0: return []` or `N = max(0, N)`.
These two do not.

## Root cause

Each site computes a slice with no `N < 0` guard. A negative `N` flips the
slice: `list[:-1]` (via `[:steps]` with `steps=-1`) returns all-but-last, and
`backups[:-keep]` with `keep=-1` becomes `backups[1:]`. The contract — "return
the top N / keep the most recent N, `[]` when `N < 0`" — is violated.

## Expected per docs

ARCH-17 (issue #1049) class contract: a "top N / limit / count" truncation must
guard `N < 0 -> []`. For `steps < 0`, `rollback` must roll back **0** migrations
(return `[]`); for `keep < 0`, `cleanup_old_backups` must delete **0** backups
(return `[]`). The fix is to add `if N <= 0: return []` (matching the guarded
siblings) at each of the two sites.
