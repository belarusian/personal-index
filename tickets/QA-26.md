# QA-26: `personal-index health` crashes (TypeError) on a page with a null title/content field

- Status: IMPLEMENTED #1288@d0f6b39
- Kind: QA
- Component: `personal_index/content_health.py` (`_check_title_length`,
  `_check_content_length`), reached via `personal_index/cli_health.py`
  (`personal-index health`) and the public `ContentHealthChecker.check_item` /
  `check_all` API
- Class home: ARCH-63 (docs/CONTRACTS.md "Defensive-load guard (binding)")
- Issue: #1241
- Deep test: `tests/deep/test_content_health_adversarial.py`
  (4 xfail-strict defect pins + 43 clean armor tests)

## Symptom

`personal-index health` crashes with `TypeError: object of type 'NoneType' has
no len()` (exit code 1, empty output) when a page in `search_index.json` is a
valid dict whose `title` (or `content`) field is `null`.

This is a DISTINCT defect from QA-20 (issue #1219): QA-20 is the `_load`
crash on a **non-dict page value** (e.g. `{"u": "notadict"}`) in the store
`_load` methods. Here the page **is** a valid dict; the crash is in a
**downstream consumer** (`content_health.py`) on a **null field**, reached
through the public `health` CLI.

## Root cause

`content_health.py`:
- `_check_title_presence` (line 225) guards with `if title and len(title) >= ...`,
  so a `None` title passes through as falsy (no issue appended).
- `_check_title_length` (line 240) then calls `len(title)` **unguarded** ->
  `len(None)` -> `TypeError`.
- `_check_content_length` (line 255) calls `len(content)` **unguarded** -> same
  crash for `content=None`.

The CLI (`cli_health.py:_build_health_items`) coerces `content`
(`"content": page.content or ""`) but NOT `title` (`"title": page.title`), so a
null title flows straight into `check_item`. This internal inconsistency
(coerce content, not title) shows null fields are in-scope for the
defensive-load contract.

## Exact repro

    python3 -c "import json,os,tempfile;from click.testing import CliRunner;from personal_index.cli import main;dd=tempfile.mkdtemp();os.makedirs(dd);json.dump({'pages':{'http://example.com':{'url':'http://example.com','title':None,'content':'x'*60,'score':1.0,'status_code':200}},'word_index':{}},open(os.path.join(dd,'search_index.json'),'w'));json.dump({'tags':{},'page_tags':{}},open(os.path.join(dd,'tags.json'),'w'));r=CliRunner().invoke(main,['health','--data-dir',dd]);print(r.exit_code,repr(r.output))"

Output: `1 ''` (crash).

## Expected per docs

ARCH-63 defensive-load contract: a malformed index must degrade to the empty
state / a per-item issue, never crash the whole command. `check_item` should
treat a `None` title/content as empty (flag `missing_title` / `low_content`)
rather than raise. The CLI should coerce `title` the same way it coerces
`content` (`page.title or ""`).
