# QA-62: ContentArchiver.archive_old silently skips parseable naive `saved_at` timestamps

- **Status:** OPEN
- **Component:** `personal_index/content_archive/archiver.py` (`ContentArchiver.archive_old`)
- **Kind:** contract violation (docstring says non-None `archived_at` are considered; only unparseable values skipped)
- **Issue:** #1703
- **Deep test:** `tests/deep/test_content_archive_naive_adversarial.py`

## Symptom

`archive_old` parses `saved_at` with `datetime.fromisoformat(saved_at)` and
compares `saved_time < cutoff`, where `cutoff` is UTC-**aware**
(`datetime.now(timezone.utc) - timedelta(days=threshold)`). A **naive** ISO
timestamp (no `+00:00` / `Z` suffix) parses successfully — it is NOT
"unparseable" — but `naive < aware` raises `TypeError`, which the
`except (ValueError, TypeError): pass` clause swallows. The item is silently
skipped and stays `ACTIVE`, even when it is far older than the threshold.

The docstring contract (archiver.py, `archive_old`) states:

> "Only items whose ``archived_at`` field is non-None are considered; ...
>  Unparseable ``archived_at`` values are silently skipped."

A naive ISO string is parseable and non-None, so the contract requires it to
be considered and archived when old. It is instead dropped. This is also
inconsistent with `content_scoring._score_recency`, which explicitly
normalizes naive datetimes to UTC before comparing.
