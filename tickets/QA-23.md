# QA-23: SitemapBuilder.build()/build_sitemap_index() emit no sitemap namespace

Status: CLAIMED 2026-09-12
Priority: medium
Component: personal_index/sitemap_builder.py
Filed: Cycle 189
Issue: #1228
Deep test: tests/deep/test_sitemap_builder_adversarial.py::TestQA23Namespace

## Summary

`SitemapBuilder.build()` and `build_sitemap_index()` construct their root
element with `Element("urlset", nsmap=NSMAP)` / `Element("sitemapindex",
nsmap=NSMAP)`. `xml.etree.ElementTree.Element` has **no `nsmap` parameter** —
any extra keyword is stored as a literal XML *attribute*. So the serialized
output is a bare `<urlset nsmap="{'': 'http://www.sitemaps.org/schemas/sitemap/0.9'}">`
with **no `xmlns` namespace declaration**, and the `nsmap` dict leaks as a
garbage string attribute.

`docs/content-sitemap.md` (Public API — `personal_index.sitemap_builder`)
promises:

> `build() -> bytes` — a `<urlset>` root (**with the sitemap namespace**), one
> `to_element()` per entry, ...

and the same for `build_sitemap_index()` ("a `<sitemapindex>` root ... same
XML-declaration prefix"). The namespace is promised but never emitted.

## Consequence (round-trip broken)

The package's own `SitemapParser` reads entries under the sitemap namespace
(`root.findall("ns:url", {"ns": "http://www.sitemaps.org/schemas/sitemap/0.9"})`).
Because the builder's output has no namespace, `SitemapParser().parse(builder.build())`
returns **zero entries** — the documented build→parse round-trip is broken.

## Repro

    python3 -c "
    from personal_index.sitemap_builder import SitemapBuilder
    from personal_index.sitemap import SitemapParser
    b = SitemapBuilder()
    b.add_entry('https://x.com/1')
    raw = b.build().decode('utf-8')
    print(raw)
    print('xmlns present:', 'xmlns' in raw)
    print('nsmap attr leaked:', 'nsmap=' in raw)
    print('parsed entries:', SitemapParser().parse(raw).get_urls())
    "

Actual output:

    <?xml version="1.0" encoding="UTF-8"?>
    <urlset nsmap="{'': 'http://www.sitemaps.org/schemas/sitemap/0.9'}"><url><loc>https://x.com/1</loc>...</url></urlset>
    xmlns present: False
    nsmap attr leaked: True
    parsed entries: []

Expected per docs: the root carries the sitemap namespace
(`<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">`), no literal
`nsmap=` attribute, and `SitemapParser().parse(...).get_urls() ==
['https://x.com/1']`.

## Expected per docs

- `build()` root tag is `{http://www.sitemaps.org/schemas/sitemap/0.9}urlset`.
- `build_sitemap_index()` root tag is `{http://www.sitemaps.org/schemas/sitemap/0.9}sitemapindex`.
- No literal `nsmap=` attribute in the serialized bytes; a real `xmlns` declaration is present.
- `SitemapParser().parse(builder.build())` recovers the same URLs, changefreq, priority, lastmod.

## Fix direction (implementer)

Apply the namespace correctly, e.g. register the prefix and build the root
with a qualified tag:

    ET.register_namespace("", SM_NS)
    root = Element(f"{{{SM_NS}}}urlset")

(or use `ElementTree`/`SubElement` with the qualified tag). Then the
`TestQA23Namespace` xfail-strict pins flip to hard passes.
