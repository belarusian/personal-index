# QA-19: InterestStore.get_all_keywords / get_all_topics crash on non-string elements

- Status: IMPLEMENTED #1274@65c8bff378527b94ac3250a1da42709cf96edd92
- Component: `personal_index/interests.py`
- Issue: #1211

## Symptom

`InterestStore.get_all_keywords` (line 97) and `get_all_topics` (line 116)
call `.lower()` on every element of `interest.keywords` /
`interest.topics` with **no `isinstance(..., str)` guard**:

    personal_index/interests.py:97   keywords.add(kw.lower())
    personal_index/interests.py:116   topics.add(topic.lower())

If a list element is not a string (e.g. `int` or `None`), this raises
`AttributeError: 'int' object has no attribute 'lower'` (or
`'NoneType' object has no attribute 'lower'`).

This is inconsistent with the rest of the module, which uniformly treats
non-string elements as skippable:

- `InterestStore.get_all_url_patterns` (same file, line 105) explicitly
  guards: `if not isinstance(pattern_str, str): continue`.
- `Interest.matches` (models.py:118,121) guards:
  `if isinstance(kw, str) and kw.lower() in text_lower:` and the same for
  topics.
- `Interest.score` (models.py:163,166) guards: `if isinstance(kw, str):`.

So the module's established contract is that non-string keyword/topic
elements are silently skipped, not fatal. `get_all_keywords` and
`get_all_topics` are the two aggregation methods that violate it.

A non-string element is reachable in practice: `Interest.__post_init__`
coerces a non-list `keywords` to `[]` but does NOT filter non-string
members of a list, so `Interest(name="a", keywords=["ok", 42, None])`
stores the list verbatim and `get_all_keywords()` then crashes.

## Repro

    python3 -c "from personal_index.interests import InterestStore; from personal_index.models import Interest; s=InterestStore(store_path=None); s.add(Interest(name='a', keywords=['ok', 42, None])); print(s.get_all_keywords())"

Expected per module contract (consistent with `get_all_url_patterns` /
`matches` / `score`): non-string elements are skipped, returning `{"ok"}`.
Actual:

    AttributeError: 'int' object has no attribute 'lower'

Same for topics:

    python3 -c "from personal_index.interests import InterestStore; from personal_index.models import Interest; s=InterestStore(store_path=None); s.add(Interest(name='a', topics=['ok', 42, None])); print(s.get_all_topics())"

    AttributeError: 'int' object has no attribute 'lower'

Traceback (keywords):

    File ".../personal_index/interests.py", line 97, in get_all_keywords
        keywords.add(kw.lower())
    AttributeError: 'int' object has no attribute 'lower'

## Deep test

`tests/deep/test_interests_adversarial.py::TestAggregation::test_get_all_keywords_skips_non_str`
and `tests/deep/test_interests_adversarial.py::TestAggregation::test_get_all_topics_skips_non_str`
are xfail-strict with reason referencing QA-19.

## Minimal additive fix (for implementer)

Add the same guard the sibling methods already use:

    for kw in interest.keywords:
        if not isinstance(kw, str):
            continue
        keywords.add(kw.lower())

and analogously for `topics` in `get_all_topics`.
