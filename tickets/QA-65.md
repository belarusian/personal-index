# QA-65: FacetedSearch range filter raises uncaught TypeError on a naive-vs-aware datetime mismatch

- **Status:** CLAIMED 2026-09-21
- **Component:** `personal_index/search_facets/faceted_search.py` (`FacetedSearch._parse_date_value` -> `_matches_range_filter` -> `_check_{between,gte,lte,gt,lt}`, lines 239-271)
- **Kind:** contract violation (uncaught `TypeError` — naive-vs-aware datetime seam)
- **Issue:** #1720
- **Deep test:** `tests/deep/test_search_facets_naive_aware_adversarial.py`
- **Class:** naive-vs-aware datetime comparison (same class as QA-62/63/64; `content_scoring._score_recency` is the reference fix that normalizes naive -> UTC)

## Symptom

`FacetedSearch.search(query, filters={...})` applies a range filter
(`$gte`/`$lte`/`$gt`/`$lt`/`$between`) on a document field. `_parse_date_value`
(faceted_search.py:289) parses an ISO string with `datetime.fromisoformat` and
returns the resulting datetime. `_matches_range_filter` (faceted_search.py:207)
then compares the parsed DOCUMENT value against the parsed filter BOUND in
`_check_*` (faceted_search.py:239/247/255/263/271).

When the document value is a **naive** ISO string (no `+00:00`/`Z` suffix) and
the filter bound is an **aware** ISO string (or vice-versa), the comparison
`val >= pv` / `val <= pv` / `val < pv` / `val > pv` / `lp <= val <= hp` raises
`TypeError: can't compare offset-naive and offset-aware datetimes`. No `except`
clause catches it, so the exception propagates out of `search()`.

This is the same naive-vs-aware datetime seam class as:
  * QA-62 (content_archive.archive_old — VERIFIED, fixed in #1715)
  * QA-63 (sitemap.get_recent_entries + progress.elapsed_seconds — OPEN)
  * QA-64 (auth/api_keys.validate_key — OPEN)

The search_facets/faceted_search.py range-filter site is a NEW,
previously-unfiled member of that class.

## Expected per docs

`_parse_date_value` documents that it "returns a datetime object for ISO format
strings". A naive ISO string is a valid ISO format and parses successfully. The
range filter should compare a naive document value against an aware bound the
same way it compares two aware values: normalize a naive datetime to UTC-aware
(e.g. `dt.replace(tzinfo=timezone.utc)` when `dt.tzinfo is None`) before
comparing — exactly the reference fix in
`content_scoring._score_recency` (content_scoring.py:267-268). After the fix, a
naive document value within an aware range bound should match (total reflects
the correct range semantics), and the reverse (aware doc vs naive bound) should
also match.

## Asymmetry (same doc, same bound, only tz-awareness differs)

    naive doc  vs aware bound -> RAISES TypeError (defect)
    aware doc  vs aware bound -> matches (correct)
    naive doc  vs naive bound -> matches (correct)
    aware doc  vs naive bound -> RAISES TypeError (defect, reverse direction)

All five range operators (`$gte`/`$lte`/`$gt`/`$lt`/`$between`) are affected.

## Deep test

`tests/deep/test_search_facets_naive_aware_adversarial.py` — 6 xfail-strict pins
(one per affected operator/direction) that fail on current main and must be
flipped to hard passes once the implementer's fix is confirmed ON main; plus
armor (both-aware / both-naive no-seam cases, None/non-date/out-of-range guard
inputs) and one end-to-end CLI run.
