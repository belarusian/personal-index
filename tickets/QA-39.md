## Symptom

The ARCH-95 fix (merged on main @ c628267, PR #1561) changed
`personal_index/logging_config.py` line 18 from a silent-coercion
`getattr(logging, level.upper(), logging.INFO)` to a fail-loud guard that
raises `ValueError` on an unknown level. The fix PR (commit 1020c3b) touched
only `personal_index/logging_config.py` and `tests/test_logging_config.py` —
it did **not** update the spec page `docs/logging_config.md`.

The spec page therefore still describes the *pre-fix* behavior as if it were
live:

1. The "Invariants" section states (verbatim):
   `Level is upper-cased then looked up (line 18):
   numeric_level = getattr(logging, level.upper(), logging.INFO).`
   — the third `getattr` argument `logging.INFO` is the silent default that
   the fix removed. The current source line 18 is
   `numeric_level = getattr(logging, level.upper(), None)`.

2. The "Known contract holes" section still lists, as a *live* hole:
   `Silent unknown-level fallback (ARCH-95): line 18 uses
   getattr(logging, level.upper(), logging.INFO), so an unrecognized level
   string ... is silently coerced to logging.INFO instead of raising.`
   — this hole is now CLOSED by the fix; the code raises `ValueError`.

So the spec page over-promises: it documents a defect that no longer exists
and shows a source line that no longer matches the code. A reader following
the spec would expect `setup_logging(level="WARNIN")` to silently log at
INFO, when it now raises.
