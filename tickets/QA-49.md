# QA-49: annotation `AnnotationStore.get_stats()` — `urls_annotated` over-counts URLs whose index list is empty (left behind by `add()` upsert reconciliation and `remove()`)

Status: VERIFIED (cycle 304)
Issue: #1630
Component: `personal_index/annotation.py` (`AnnotationStore.get_stats` line 220 — `"urls_annotated": len(self._by_url)`; the empty index lists are produced by `add` line 98 `old_ids.remove(annotation.annotation_id)` leaving `self._by_url[old_url] == []`, and by `remove` line 168 `self._by_url[annotation.url] = [aid for aid in ... if aid != annotation_id]` which can yield `[]`)
Refs: `AnnotationStore.get_stats` docstring ("number of annotated URLs"); `AnnotationStore.add` docstring postcondition ("each id maps to exactly one URL")
Deep test: tests/deep/test_annotation_adversarial.py (TestStats::test_urls_annotated_excludes_empty_index_after_upsert and TestStats::test_urls_annotated_excludes_empty_index_after_remove — both xfail-strict)

## Symptom

`get_stats()["urls_annotated"]` is computed as `len(self._by_url)`, i.e. the
number of KEYS in the URL index. But the index can hold EMPTY lists for URLs
that no longer have any annotation, so the count includes URLs with zero
annotations. The docstring promises "number of annotated URLs" — a URL whose
index list is empty has no annotations and must not be counted.

Two code paths leave an empty index list behind:

### Path 1 — `add()` upsert reconciliation (line 98)

When an annotation id is re-added under a DIFFERENT url, `add` removes the id
from the old url's index list (`old_ids.remove(annotation.annotation_id)`). If
that was the old url's only annotation, the old url's list becomes `[]` but the
KEY stays in `self._by_url`. The new url gets its own list. So one annotation
now maps to one url (postcondition holds for `get_by_url`, which filters by
`aid in self._annotations`), yet `urls_annotated` counts BOTH urls.

### Path 2 — `remove()` (line 168)

`remove` rewrites the url's index list to exclude the removed id. If that was
the url's last annotation, the list becomes `[]` but the key stays. So after
removing every annotation for a url, `urls_annotated` still counts that url.

## Repro

    from personal_index.annotation import Annotation, AnnotationStore, AnnotationType

    def ann(aid, url):
        return Annotation(annotation_id=aid, url=url, annotation_type=AnnotationType.NOTE)

    # Path 1: upsert same id to a new url
    s = AnnotationStore()
    s.add(ann("a", "http://u1"))
    s.add(ann("a", "http://u2"))
    print(s.get_by_url("http://u1"))   # -> []  (u1 has no annotations)
    print(s.get_stats())
    # -> {'total': 1, 'by_type': {'note': 1}, 'urls_annotated': 2}
    #    expected urls_annotated == 1 (only u2 is annotated)

    # Path 2: remove every annotation for a url
    s2 = AnnotationStore()
    s2.add(ann("a", "http://u1"))
    s2.add(ann("b", "http://u1"))
    s2.remove("a")
    s2.remove("b")
    print(s2.get_by_url("http://u1"))  # -> []
    print(s2.get_stats())
    # -> {'total': 0, 'by_type': {}, 'urls_annotated': 1}
    #    expected urls_annotated == 0

## Expected per docs

`urls_annotated` should count only URLs that currently have at least one
annotation. Minimal fix: count non-empty index lists, e.g.

    "urls_annotated": sum(1 for ids in self._by_url.values() if ids)

or prune empty lists at the mutation sites (`add` reconciliation and `remove`)
so `self._by_url` never holds an empty list. Either fix makes the "number of
annotated URLs" contract hold. Note `get_by_url` already tolerates the empty
lists (it filters by `aid in self._annotations`), so only `get_stats` is
affected.
