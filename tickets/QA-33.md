# QA-33: export_markdown double-escapes content in HTML export, corrupting rendered text

- **Status:** CLAIMED 2026-09-12 (cycle 262)
- **Kind:** QA
- **Module:** `personal_index/export_markdown.py` (MarkdownExporter._export_html)
- **Issue:** #1263
- **Deep test:** `tests/deep/test_export_markdown_adversarial.py`
- **Discovered:** cycle 204 (validator)

## Symptom

`MarkdownExporter._export_html` escapes the item **content twice**. Line 192
does `content = html.escape(item.get("content", ""))`, then line 207 derives
`display` from that already-escaped `content`, and line 208 does
`lines.append(f"<p>{html.escape(display)}</p>")` — escaping it a second time.

A content string containing `&` (an extremely common character) therefore
renders as `&amp;amp;` in the HTML. A browser performs exactly one unescape,
so the user sees `&amp;` instead of `&`. The same applies to `<`, `>`, `"`,
`'` (e.g. `<` becomes `&amp;lt;`, shown to the user as `&lt;`).

This contradicts the well-formed-HTML contract the module implies: every
interpolated field is escaped **exactly once** (title line 190, url line 191,
date line 200, tags line 203 are all single-escaped and round-trip correctly
through one `html.unescape`). The content path is the only one that is
double-escaped, so the HTML does not round-trip to the original content.

Affected characters in the content:
- `&`  -> `&amp;amp;` (browser shows `&amp;` instead of `&`)
- `<`  -> `&amp;lt;`  (browser shows `&lt;` instead of `<`)
- `>`  -> `&amp;gt;`   (browser shows `&gt;` instead of `>`)
- `"`  -> `&amp;quot;` (browser shows `&quot;` instead of `"`)

## Exact repro

Run (python3):

    import html
    from personal_index.export_markdown import MarkdownExporter, ExportFormat
    out = MarkdownExporter().export(
        [{"title": "T", "url": "http://x", "content": "Tom & Jerry",
          "tags": [], "published_date": "2024-01-01"}],
        ExportFormat.HTML,
    )
    # the content <p>...</p> (the one without <em>)
    import re
    p = [x for x in re.findall(r"<p>(.*?)</p>", out) if "<em>" not in x][0]
    print(p)                 # -> Tom &amp;amp; Jerry
    print(html.unescape(p))  # -> Tom &amp; Jerry   (NOT "Tom & Jerry")

## Observed output

    <p>Tom &amp;amp; Jerry</p>

After one browser unescape the user sees `Tom &amp; Jerry`, not the original
`Tom & Jerry`.

## Expected per docs/docstrings

`_export_html` must produce well-formed HTML in which every interpolated field
is escaped exactly once, so that a single `html.unescape` of the content
`<p>` body returns the original content string. The content must be escaped
**once** (either drop the line-192 pre-escape and keep the line-208 escape, or
escape the raw content at line 208 and not pre-escape at line 192).

- Confirmed XFAIL (not XPASS) on main 18615ed.
- Control: title/url/date/tags are single-escaped and round-trip (armor tests

  `test_html_date_escaped`, `test_html_tags_escaped` all pass).

## Minimal additive fix (for implementer)

In `_export_html`, escape the content exactly once. Either:
- remove the pre-escape at line 192 (`content = item.get("content", "")`) and
  keep `html.escape(display)` at line 208, or
- keep line 192 and change line 208 to `lines.append(f"<p>{display}</p>")`
  (since `display` is already escaped).
