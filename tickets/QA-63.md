# QA-63: naive-vs-aware datetime seam - parseable naive timestamps mishandled at two public sites

- **Status:** CLAIMED 2026-09-21
- **Component:** `personal_index/sitemap.py` (`SitemapParser.get_recent_entries`) + `personal_index/progress.py` (`ProgressTracker.elapsed_seconds`)
- **Kind:** contract violation (docstring says only *unparseable* values are skipped; a naive ISO string is parseable and non-None)
- **Issue:** #1705
- **Deep test:** `tests/deep/test_datetime_naive_aware_adversarial.py`
- **Class:** naive-vs-aware datetime comparison (same class as QA-62; `content_scoring._score_recency` is the reference fix that normalizes naive -> UTC)

## Symptom

Two public sites parse a possibly-naive ISO string with `datetime.fromisoformat`
and then compare it to an internal `datetime.now(timezone.utc)` WITHOUT
normalizing naive -> aware first. A **naive** ISO timestamp (no `+00:00` / `Z`
suffix) parses successfully - it is NOT "unparseable" - but `naive < aware` /
`aware - naive` raises `TypeError`.

**Site 1 - `SitemapParser.get_recent_entries` (sitemap.py:198-209).** The
docstring contract states:

> "Each remaining ``lastmod`` is parsed with ``datetime.fromisoformat`` ...
>  entries whose ``lastmod`` raises ``ValueError`` or ``TypeError`` are
>  skipped. An entry is included when
>  ``(datetime.now(timezone.utc) - lastmod).days <= days``."

A naive `lastmod` parses fine, so it MUST be considered. Instead the
`naive < aware` `TypeError` is swallowed by `except (ValueError, TypeError):
pass` and the entry is **silently dropped** even when it is within the window.

**Site 2 - `ProgressTracker.elapsed_seconds` (progress.py:81-90).** The
subtraction `now - start` is OUTSIDE the `try` block, so the `TypeError`
**propagates** and the property hard-crashes on a naive `started_at`.

Both are inconsistent with `content_scoring._score_recency`, which explicitly
normalizes naive datetimes to UTC (`date.replace(tzinfo=timezone.utc)`) before
comparing to an aware cutoff.

## Exact repro

    $ python3 -c "
    from personal_index.sitemap import Sitemap, SitemapEntry, SitemapParser
    sm = Sitemap(entries=[SitemapEntry(loc='http://x', lastmod='2020-01-01T00:00:00')])
    print('naive recent:', SitemapParser().get_recent_entries(sm, days=3650))
    sm.entries = [SitemapEntry(loc='http://x', lastmod='2020-01-01T00:00:00+00:00')]
    print('aware recent:', SitemapParser().get_recent_entries(sm, days=3650))
    from personal_index.progress import ProgressTracker
    pt = ProgressTracker(operation_name='op', total_steps=10, current_step=5)
    pt.started_at = '2020-01-01T00:00:00'
    print('naive elapsed:', pt.elapsed_seconds)
    "

Output (current main b30c756):

    naive recent: []
    aware recent: [SitemapEntry(loc='http://x', lastmod='2020-01-01T00:00:00+00:00', changefreq='monthly', priority=0.5)]

    TypeError: can't subtract offset-naive and offset-aware datetimes

## Expected per docs

- `get_recent_entries`: a parseable naive `lastmod` within the window is
  included (only genuinely unparseable values are skipped).
- `elapsed_seconds`: a naive `started_at` is treated as UTC and returns a
  non-negative float (matching `content_scoring`'s naive -> UTC normalization).
