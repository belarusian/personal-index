# QA-24: CLI `recommend` advertises weight options that are accepted but never used

Status: OPEN
Priority: medium
Component: personal_index/cli_recommend.py
Filed: Cycle 192
Issue: #1233
Deep test: tests/deep/test_cli_recommend_adversarial.py::TestCliRecommendWeightsDefect

## Summary

`personal_index/cli_recommend.py` registers the `recommend` command with three
weight options, each with help text that promises they influence scoring:

    @click.option("--keyword-weight", default=0.6, help="Keyword overlap weight")
    @click.option("--tag-weight",     default=0.3, help="Tag similarity weight")
    @click.option("--score-weight",   default=0.1, help="Score weight")

The `recommend(...)` function signature accepts `keyword_weight`, `tag_weight`,
and `score_weight`, but the **function body never reads any of them**. It only
uses `query`, `top_n`, and `data_dir`, then calls:

    recs = recommender.recommend_for_keywords(keywords, top_n=top_n)

`Recommender.recommend_for_keywords(keywords, top_n)` (content_recommender.py:190)
does **not** accept weight parameters at all — its score is the fixed
`len(common) / len(query)` keyword-match fraction. The weight options are
therefore parsed, accepted, and silently discarded. A user who tunes
`--keyword-weight` / `--tag-weight` / `--score-weight` gets byte-identical
output no matter what values they pass.

This is a genuine "advertised option does nothing" contract violation: the CLI
surface (option names + help text) promises weight-based scoring that the code
path does not implement.

## Consequence

- The three options are dead: `personal-index recommend python
  --keyword-weight 0.0 --tag-weight 0.0 --score-weight 0.0` and
  `personal-index recommend python --keyword-weight 1.0 --tag-weight 1.0
  --score-weight 1.0` produce **identical** output.
- Users cannot tune recommendation scoring from the CLI at all; the advertised
  knobs are a no-op.
- The seed-based `Recommender.recommend(seed, ..., keyword_weight, tag_weight,
  score_weight)` path DOES honor weights (see armor test
  `TestRecommenderEngine.test_recommend_honors_weights`), so the engine is
  capable — only the CLI wiring drops the values.

## Expected per docs

Per the advertised options and their help text ("Keyword overlap weight",
"Tag similarity weight", "Score weight"), different weight values must change
the recommendation output (scores, ordering, or which items survive). The
options should be threaded into the scoring path (e.g. extend
`recommend_for_keywords` to accept and apply the weights, or route the CLI
through a weight-aware method).

## Fix direction (implementer)

Either (a) extend `Recommender.recommend_for_keywords` to accept
`keyword_weight`/`tag_weight`/`score_weight` and fold them into the per-item
score, and pass the CLI values through; or (b) if the keyword-fraction path is
intentionally weight-free, remove the three dead options (and their help text)
so the CLI surface matches the code. Then the
`TestCliRecommendWeightsDefect.test_cli_recommend_weights_affect_output`
xfail-strict pin flips to a hard pass (for option (a)).
