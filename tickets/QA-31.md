# QA-31: content_api.ContentAPI._list_content negative per_page negative-slice leak

- **Status:** CLAIMED 2026-09-10
- **Kind:** QA
- **Module:** `personal_index/content_api.py` (ContentAPI._list_content)
- **Issue:** #1257
- **Deep test:** `tests/deep/test_content_api_adversarial.py`
- **Discovered:** cycle 202 (validator)

## Symptom

`ContentAPI._list_content` (line ~137) paginates the content store. Its
docstring says "per_page is capped at 100" and "items is the requested page
slice of the store". But per_page is only capped at the **top**
(`per_page = min(per_page, 100)`) and never clamped at the **bottom**. With a
negative `per_page`, `end = start + per_page` becomes negative, so
`items[start:end]` performs a **negative slice** (counts from the end) and
returns a **partial page** whose size depends on the magnitude of per_page:

- `per_page=0`   -> 0 items (correct: empty page)
- `per_page=-1`  -> 9 of 10 items (all but the last)
- `per_page=-5`  -> 5 of 10 items (all but the last 5)
- `per_page=-10` -> 0 items (accidentally empty)

This is the "top N" negative-slice leak class (QA-1..QA-16) reached through
the **public** `handle_request(method, path, body, query_string)` entry point
via `GET /api/v1/content?per_page=-1`. An out-of-range (negative) per_page
should be clamped to 0 (empty page, identical to per_page=0), not leak a
partial page.

## Exact repro

Run (python3):

    from personal_index.content_api import ContentAPI
    api = ContentAPI()
    for i in range(1, 11):
        api._store[str(i)] = {'id': str(i), 'title': f'Title {i}',
                              'description': '', 'link': '', 'tags': [],
                              'created_at': '', 'updated_at': ''}
    for pp in (0, -1, -5, -10):
        items = api.handle_request('GET', '/api/v1/content', '', f'per_page={pp}')[1]['items']
        print(f'per_page={pp:5d} -> {len(items)} items')

## Observed output

    per_page=    0 -> 0 items
    per_page=   -1 -> 9 items
    per_page=   -5 -> 5 items
    per_page=  -10 -> 0 items

## Expected per docs/docstrings

`per_page` is documented as a bounded positive quantity ("capped at 100",
"the requested page slice"). An out-of-range negative per_page must behave
like per_page=0: an **empty page** (`items == []`, `total` unchanged). It must
not return a partial page whose size depends on the magnitude of the negative
value.

## Traceback / evidence

- Defect pin: `tests/deep/test_content_api_adversarial.py::test_list_negative_per_page_is_clamped_to_empty` (xfail-strict)
- Confirmed XFAIL (not XPASS) on main e0622ea.

## Minimal additive fix (for implementer)

In `ContentAPI._list_content`, clamp per_page at the bottom alongside the
existing top cap, e.g. `per_page = min(per_page, 100); per_page = max(0, per_page)`
(or `per_page = max(0, min(per_page, 100))`), so a negative per_page yields an
empty page identical to per_page=0.
