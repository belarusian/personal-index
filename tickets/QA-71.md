# QA-71: ProgressTracker.progress_percent has no lower clamp (cap-without-floor)

- **Status:** OPEN
- **Component:**
  * `personal_index/progress.py` (`ProgressTracker.progress_percent`, lines ~78-82)
- **Kind:** contract violation (docstring "0-100" vs code — one-sided guard, no floor)
- **Issue:** #1749
- **Deep test:** `tests/deep/test_progress_percent_floor_adversarial.py` (3 xfail-strict pins: `test_progress_percent_negative_current_step_is_floored`, `test_progress_percent_negative_total_steps_is_floored`, `test_to_dict_progress_percent_floored`)

## Symptom

`ProgressTracker.progress_percent` docstring promises:

    """Get progress as percentage (0-100)."""

but the body clamps only the TOP, with no floor:

    @property
    def progress_percent(self) -> float:
        """Get progress as percentage (0-100)."""
        if self.total_steps == 0:
            return 0.0
        return min(100.0, (self.current_step / self.total_steps) * 100.0)

`min(100.0, ...)` caps the upper bound at 100, but there is no `max(0.0, ...)`
lower bound. A negative `current_step` or a negative `total_steps` therefore
leaks a NEGATIVE percentage, violating the documented 0-100 range. This is the
one-sided-guard (cap-without-floor) defect class already filed at QA-15/QA-16/
QA-31 (a `min(x, CAP)` without `max(0, x)` passes a positive-N check but leaks
on a negative N).

## Exact repro

    python3 -c "
    from personal_index.progress import ProgressTracker
    t = ProgressTracker(operation_name='x', total_steps=10, current_step=-5)
    print(t.progress_percent)          # -> -50.0  (contract says 0-100)
    t2 = ProgressTracker(operation_name='x', total_steps=-10, current_step=5)
    print(t2.progress_percent)         # -> -50.0
    print(t.to_dict()['progress_percent'])  # -> -50.0 (public serialization path)
    "

## Traceback / observed output

    progress_percent with current_step=-5: -50.0
    violates 0-100 contract: True
    to_dict progress_percent: -50.0
    progress_percent with total_steps=-10: -50.0

## Expected per docs

`progress_percent` must always return a value in `[0.0, 100.0]` per its
docstring "Get progress as percentage (0-100)." The fix is to add the missing
floor: `return min(100.0, max(0.0, (self.current_step / self.total_steps) * 100.0))`.

defect; they will XPASS->RED on the fix branch until the implementer adds the
