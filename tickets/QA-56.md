# QA-56: content_scoring — four one-sided-guard / missing-guard defects in factor helpers and rank() (split out of QA-47's "related findings")

**Status:** OPEN
**Issue:** #1679
**Component:** `personal_index/content_scoring.py`
  - `_score_relevance` (line 273): guard only checks `total_keywords == 0`; a negative `total_keywords` yields a negative score

  - `_score_quality` (line 315): `math.log1p` on a negative `word_count` raises `ValueError` (no floor)
  - `rank` (line 467): guard only checks `limit <= 0`; a `None` items list raises `TypeError`

## Symptom

Four distinct contract violations, all one-sided or missing guards:

1. `_score_relevance(keyword_matches, total_keywords)`: the guard is
   `if total_keywords == 0: return 0.0`. A NEGATIVE `total_keywords` (e.g. -2)
   is not caught, so `keyword_matches / total_keywords` yields a NEGATIVE
   score (e.g. `_score_relevance(1, -2)` -> -0.5) instead of clamping to the
   documented 0.0 floor.

2. `_score_engagement(view_count, bookmark_count, share_count)`: applies
   `math.log1p` to the counts with no floor. A negative count (e.g. -2) raises
   `ValueError: math domain error` instead of clamping to 0.0.

3. `_score_quality(word_count, has_images, has_code)`: applies `math.log1p` to
   `word_count` with no floor. A negative `word_count` (e.g. -2) raises
   `ValueError: math domain error` instead of clamping to 0.0.

4. `rank(items, limit)`: the guard only checks `limit <= 0`. A `None` items
   list raises `TypeError: 'NoneType' object is not iterable` instead of
   returning an empty list.

## Repro

    from personal_index.content_scoring import ContentScorer
    s = ContentScorer()
    print(s._score_relevance(1, -2))          # -0.5  (should clamp to 0.0)
    s._score_engagement(-2, 0, 0)             # ValueError: math domain error
    s._score_quality(-2, False, False)        # ValueError: math domain error
    s.rank(None)                              # TypeError: 'NoneType' object is not iterable

## Expected per docs / contract

Each factor helper is documented as a 0.0-1.0 score; `docs/CONTRACTS.md`
requires a non-positive caller-supplied bound to yield the same empty/zero
result as the zero bound. Minimal fix: clamp each helper's inputs to >= 0
before the arithmetic (e.g. `total_keywords = max(0, total_keywords)`,
`view_count = max(0, view_count)`, etc.), and guard `rank` with
`if items is None: return []`.
