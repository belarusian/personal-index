# QA-40: ContentAggregator.merge_all collapses distinct no-id/no-title items to one (silent data loss on the default path)

Status: CLOSED (validator cycle 271 @ main 76e12b6 - re-verified: merge_all no-id/no-title items keyed on positional ("__no_id_title__", index) at content_aggregator.py:48-49, never collapsed; deep test test_merge_all_missing_id_title asserts len==2 (was 1) and passes; full tests/deep/test_content_aggregator_adversarial.py 32 passed + 2 xfailed [the 2 xfails are QA-41's int-vs-str id pins, a DIFFERENT symptom, still OPEN]. Deep test: `tests/deep/test_content_aggregator_adversarial.py::test_merge_all_missing_id_title`

## Symptom
`merge_all(deduplicate=True)` (the default) builds the dedup key as
`str(item.get("id") or item.get("title"))`. An item with **both** `id` and
`title` absent yields `str(None or None)` = `"None"`. Every such item maps to
the *same* key, so only the **first** survives and the rest are silently
dropped - data loss on the default code path with no warning or error.

## Expected per docs
The docstring says "removes duplicate items keyed on the item's 'id' (falling
back to 'title'), keeping the first occurrence." ARCH-35 acceptance criterion 1
states: "Two items with no `id` and no `title` both survive `merge_all()`
(default `deduplicate=True`)." Distinct items that merely lack both keys must
NOT be collapsed.

## Traceback / evidence (pre-fix)
    python3 -m pytest tests/deep/test_content_aggregator_adversarial.py::test_merge_all_missing_id_title -q
    # pre-fix deep test pinned the OLD collapse: assert len(merged) == 1
    # the corrected contract requires len(merged) == 2

## Fix (cycle 268)
Items with both `id` and `title` absent are now keyed on a stable per-item
positional key `("__no_id_title__", index)` so they are never collapsed. The
deep test was flipped from `assert len(merged) == 1` to `assert len(merged) == 2`.
Scope is ARCH-35 criterion 1 only (the int-vs-str `str()` collapse of criteria
2/3 is a separate, still-open concern).
