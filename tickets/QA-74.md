## Symptom

`dedup_all`'s docstring documents the rebuild stages as "keeping the FIRST
item per `normalize_url(...)`" and "keeping the FIRST item per
`content_hash(...)`", and states the returned `DedupResult` has
`unique_items = len(items) - removed_count`.

The empty-key collapse is a **silent data-loss bug**: two *genuinely distinct*
items (different content) that both have an empty URL are collapsed to a
single survivor by the URL rebuild stage, but the dropped item is **never
counted in `removed_count`**. The result therefore reports
`unique_items = 2, removed_count = 0` while the pipeline actually retains only
**one** item. The same collapse applies to empty-content items in the hash
rebuild stage.

This is the same defect class as QA-40 (ContentAggregator.merge_all empty-key
collapse) but a different file and a different function.

## Exact repro

    python3 -c "from personal_index.content_dedup import ContentDeduplicator; d=ContentDeduplicator(); items=[{'url':'','content':'alpha'},{'url':'','content':'beta'}]; r=d.dedup_all(items); print(r.total_items, r.unique_items, r.removed_count, len(r.duplicate_groups))"

## Observed output

    2 2 0 0

`unique_items` is 2, but the URL rebuild stage (keeping the first item per
`normalize_url` key, where both empty URLs normalize to the empty string)
retains only `alpha`. `beta` is discarded and is neither in `removed_count`
nor in any `duplicate_groups` entry. The result object claims 2 unique items
exist when only 1 actually survives the pipeline.

## Expected per docs

Either (a) distinct-content empty-URL items are NOT collapsed (they are not
duplicates, so both should survive and be counted unique), or (b) the dropped
item is counted in `removed_count` so `unique_items` reflects the true
survivor count. As written, the result overstates the survivor count - silent
data loss with no warning, error, or group record.

## Traceback / evidence

No exception is raised (that is the point - it is silent). The survivor count
is computed by replaying the documented rebuild stages:

    python3 -c "from personal_index.content_dedup import normalize_url; items=[{'url':'','content':'alpha'},{'url':'','content':'beta'}]; seen=set(); uniq=[]; [uniq.append(it) for it in items if not (seen.add(normalize_url(it.get('url',''))) or seen.__contains__(normalize_url(it.get('url',''))))]; print('actual survivors:', [it['content'] for it in uniq])"

    actual survivors: ['alpha']
