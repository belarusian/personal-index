# QA-36: content_priority._recency_score unguarded on negative days_since_indexed — recency sub-factor and weighted total exceed the documented 0-1 range

## Symptom
`PriorityCalculator._recency_score(days_since_indexed)` is a bare
`math.exp(-days_since_indexed / 30.0)` (personal_index/content_priority.py:167-170)
with NO floor on `days_since_indexed`. A NEGATIVE `days_since_indexed` (a
future date — plausible from upstream date-math bugs) makes the recency
sub-factor EXCEED 1.0, violating its documented "0-1" range, and consequently
pushes the weighted total above 1.0, violating the documented "[0, 1] when the
config weights sum to 1.0" guarantee.

Repro (exact):

    python3 -c "
    from personal_index.content_priority import PriorityCalculator
    c = PriorityCalculator()
    print(c._recency_score(-30.0))   # 2.718281828459045  (documented range: 0-1)
    r = c.calculate('u','t', content_score=10.0, view_count=100, days_since_indexed=-30.0)
    print(round(r.score,6), r.priority.value)   # 1.043656 critical  (documented total range: [0,1])
    print({k: round(v,4) for k,v in r.breakdown.items()})
    # {'recency': 2.7183, 'content_score': 1.0, 'interest_match': 0.0, 'engagement': 1.0}
    "

## Why it is a real contract violation
- `_recency_score` docstring: "Calculate recency score (0-1, higher = more
  recent)." `math.exp(-(-30)/30) = e = 2.718 > 1.0` breaks the 0-1 contract.
- `calculate` docstring + docs/content-priority.md: the weighted total is
  "only guaranteed to be in `[0, 1]` when the config weights sum to `1.0`".
  The DEFAULT `PriorityConfig` weights sum to exactly 1.0 (0.2+0.3+0.3+0.2),
  yet `calculate(..., days_since_indexed=-30.0)` returns total 1.0437 > 1.0.
- The sibling sub-factors ALL clamp to [0,1]: `content_score` ->
  `min(max(content_score/10.0, 0.0), 1.0)`; `_engagement_score` -> `0.0` when
  `view_count <= 0` and `min(1.0, ...)`; `_interest_score` -> `min(1.0, ...)`.
  Recency is the ONLY unguarded sub-factor — a strong defect signal (same
  pattern as QA-35's unguarded `suggest`).

## Expected per docs
- `_recency_score(d)` in [0, 1] for all `d` (clamp `days_since_indexed` to
  `>= 0`, or clamp the result to [0,1]).
- `calculate(...).score` in [0, 1] when the config weights sum to 1.0.

## Fix (implementer)
In `_recency_score`, clamp the input: `days = max(0.0, days_since_indexed)`
before `math.exp(-days / 30.0)` (or clamp the returned score to [0,1]).
This makes the two xfail-strict pins in
`tests/deep/test_content_priority_adversarial.py` XPASS -> the validator
removes the markers and re-verifies.
