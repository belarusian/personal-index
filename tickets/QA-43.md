# QA-43: content_batch guard-parameter class — non-positive batch_size / max_retries break the documented invariant (batch_size=0 crashes; <0 / max_retries<=0 silently vanish items)

Status: VERIFIED (validator cycle 294 @ main 190929a; content_batch clamps batch_size and max_retries to >= 1; deep tests tests/deep/test_content_batch_adversarial.py 29 passed incl. test_batch_size_zero_clamped and test_max_retries_zero_clamped; Issue #1600 remains open for implementer fix)
Component: `personal_index/content_batch.py`
Issue: #1610
Refs: docs/content-batch.md (ARCH-52 resolved invariant), QA-35/QA-36 (negative-guard clamp class)
Deep test: tests/deep/test_content_batch_adversarial.py (TestGuardParameterClass, 4 xfail-strict pins)

## Symptom

`BatchProcessor` takes `batch_size: int = 100` and `max_retries: int = 3` with
**no documented clamp** on either. The docs (docs/content-batch.md, "Contract
holes", ARCH-52 resolved) promise the invariant:

    processed + failed == total_items holds for any processor exception.

That invariant holds for **valid** guard params (verified: `batch_size=2` /
`max_retries=3` with a failing processor -> processed=0 failed=5 total=5). But
for **non-positive** guard params the invariant breaks in two distinct ways:

1. **`batch_size=0` -> unhandled crash.** `process()` runs
   `for i in range(0, total, self.batch_size)`; `range(0, 5, 0)` raises
   `ValueError: range() arg 3 must not be zero`. The exception is raised in the
   *chunking* loop, OUTSIDE `_process_single_batch`'s try/except, so it is NOT
   isolated into `result.errors` — it propagates out of `process()` and aborts
   the run. This directly contradicts the ARCH-52 contract ("any Exception ...
   is isolated ... the run continues").

2. **`batch_size<0` and `max_retries<=0` -> silent item vanish.**
   `range(0, total, negative)` is empty, so `process()` processes zero batches
   and returns `processed=0, failed=0, total=N`. The N input items are neither
   processed nor counted as failed — they silently disappear, and
   `processed + failed (0) != total_items (N)`. Same for
   `process_with_retry(..., max_retries=0)` / `max_retries=-1`
   (`range(max_retries)` empty).

This is the guard-parameter class (cf. QA-35 `suggest()` negative
max_suggestions, QA-36 `_recency_score` negative days): a parameter that
accepts a non-positive value with no clamp, where the failure mode is either an
unhandled crash or a silent no-op that violates a documented invariant.

## Repro

    from personal_index.content_batch import BatchProcessor
    items = [{"id": i} for i in range(5)]

    # (1) batch_size=0 -> unhandled ValueError (crash, not isolation)
    BatchProcessor(batch_size=0).process(items)
    # ValueError: range() arg 3 must not be zero

    # (2) batch_size<0 -> silent vanish
    r = BatchProcessor(batch_size=-1).process(items)
    print(r.processed, r.failed, r.total_items)   # 0 0 5  (invariant broken)

    # (3) max_retries<=0 -> silent vanish
    r = BatchProcessor().process_with_retry(items, max_retries=0)
    print(r.processed, r.failed, r.total_items)   # 0 0 5  (invariant broken)
    r = BatchProcessor().process_with_retry(items, max_retries=-1)
    print(r.processed, r.failed, r.total_items)   # 0 0 5  (invariant broken)

## Expected per docs

docs/content-batch.md (ARCH-52 resolved): "any `Exception` raised by the
processor ... is isolated into `result.errors` and the run continues;
`processed + failed == total_items` holds for any processor exception." The
chunking loop's `range()` ValueError for `batch_size=0` is an `Exception` that
is NOT isolated (it aborts the run), and the silent no-op for
`batch_size<0` / `max_retries<=0` violates the invariant. Expected: clamp
`batch_size` to `>= 1` (or treat `<=0` as a documented no-op that still
satisfies the invariant) and `max_retries` to `>= 1`, so the invariant holds
for every guard-param value.

## Fix (implementer)

In `BatchProcessor.process` / `process_with_retry` (and the `__init__`
default), clamp the guard params before chunking, e.g.
`self.batch_size = max(1, batch_size)` and `max_retries = max(1, max_retries)`,
so `range()` is never zero/negative and the ARCH-52 invariant holds for all
inputs. Then flip the 4 xfail-strict pins in
tests/deep/test_content_batch_adversarial.py::TestGuardParameterClass to plain
asserts.
