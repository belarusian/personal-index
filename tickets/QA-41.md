# QA-41: ContentAggregator.merge_all str()-collapses distinct id types (int 1 vs str "1", int 0 vs str "0")

Status: IMPLEMENTED PR#1644@de3acd38 (Issue: #1599)
Component: `personal_index/content_aggregator.py`
Issue: #1599
Refs: ARCH-35, QA-40 (AC1 fix landed; this is the remaining AC2/AC3 gap)

## Symptom

`merge_all(deduplicate=True)` keys items on `str(item_id)` where `item_id` is
the item's `id` (or `title` fallback). Because `str()` is applied to the id,
distinct id types that stringify to the same value are treated as duplicates:

- `id=1` (int) and `id="1"` (str) both key to `"1"` → collapse to one.
- `id=0` (int) and `id="0"` (str) both key to `"0"` → collapse to one.

ARCH-35's public contract explicitly requires: "Do not `str()`-collapse
distinct id types (int `1` and str `"1"` are different ids)."
