# QA-20: defensive-load-crash CLASS sweep — 5 NEW public sites crash on a non-dict value

- Status: CLAIMED 2026-09-12
- Kind: QA
- Component: `personal_index/index.py`, `personal_index/search_index.py`,
  `personal_index/tags.py`, `personal_index/interests.py`,
  `personal_index/migrations/base.py` (one class, five sites)
- Class home: ARCH-63 (docs/CONTRACTS.md "Defensive-load guard (binding)")
- Per-site instances already filed: QA-11 (domains, CLOSED/fixed), QA-17
  (content_pin, OPEN)
- Issue: #1219
- Deep test: `tests/deep/test_defensive_load_sweep_adversarial.py`
  (5 xfail-strict site pins + 1 xfail-strict CLI end-to-end + clean armor)

## Symptom

The defensive-load-crash class (ARCH-63) is filed at 2+ sites (QA-11 domains,
QA-17 content_pin). A whole-codebase sweep of the pattern — a `_load` method
that `json.load`s a file, checks `isinstance(data, dict)`, then iterates
`.items()` constructing a per-key object — found FIVE NEW public sites whose
`except` tuple does NOT cover the value-shape error a non-dict value raises.
A valid-JSON file that maps a key to a non-mapping value (e.g.
`{"u": "notadict"}`) therefore propagates out of `__init__` /
`__post_init__` and fails the WHOLE object construction instead of degrading
to the empty state.

| # | Site | Method | Per-value construction | except tuple | Crash on non-dict value |
|---|------|--------|------------------------|--------------|--------------------------|
| 1 | `index.py` | `SearchIndex._load` | `IndexedPage.from_dict(d)` | `(JSONDecodeError, KeyError, TypeError)` | `AttributeError: 'str' object has no attribute 'items'` |
| 2 | `search_index.py` | `SearchIndex._load` | `CrawledPage.from_dict(page_data)` | `(JSONDecodeError, KeyError)` | `AttributeError: 'str' object has no attribute 'get'` |
| 3 | `tags.py` | `TagStore._load` | `Tag(... tag_data.get(...))` | `(JSONDecodeError, KeyError, TypeError)` | `AttributeError: 'str' object has no attribute 'get'` |
| 4 | `interests.py` | `InterestStore._load` | `Interest.from_dict(d)` | `(JSONDecodeError, KeyError, TypeError)` | `AttributeError: 'str' object has no attribute 'get'` |
| 5 | `migrations/base.py` | `MigrationStore._load` | `MigrationRecord(**record_data)` | `(JSONDecodeError, FileNotFoundError)` | `TypeError: MigrationRecord() argument after ** must be a mapping, not str` |

Note site 1: `IndexedPage.from_dict` does `data.items()`; a `str` value raises
`AttributeError` (not in the tuple). Sites 2/3/4 call `.get` on the value.
Site 5 splats `**record_data` on a `str`.

The already-safe sites (verified clean, pinned as armor in the same deep test):
`content_versioning.py` (TypeError in tuple), `domains.py` (isinstance filter +
TypeError/ValueError in tuple, QA-11 fixed), `scheduler.py` `ScheduleStore`
(TypeError+ValueError in tuple), `content_pin.py` top-level guard (the non-dict
VALUE crash there is QA-17).

## Deep test

`tests/deep/test_defensive_load_sweep_adversarial.py` pins each of the five
sites as `xfail-strict` (asserting the empty-state accessor) plus one
`xfail-strict` CLI end-to-end (`health` on a malformed `search_index.json`),
and pins the already-safe sites as clean armor.

## Notes

This is a CLASS ticket (one ticket, all remaining sites) per the CLASS SWEEP
rule — the same defect shape as QA-11/QA-17, not a new class. Fix is the
implementer's: broaden each `except` tuple (or wrap per-value construction) so
a non-dict value degrades to the empty state and never propagates out of
construction. Validator will re-run the deep test and flip the xfails to hard
passes when the guard lands.
