# QA-66: DashboardAggregator._compute_pages_per_day raises uncaught TypeError on a naive-vs-aware datetime mismatch

- **Status:** IMPLEMENTED #1740@2776ea8b
- **Component:** `personal_index/dashboard/aggregator.py` (`DashboardAggregator.aggregate` -> `_apply_page_stats` -> `_compute_pages_per_day`, span line 93)
- **Kind:** contract violation (uncaught `TypeError` — naive-vs-aware datetime seam)
- **Issue:** #1723
- **Deep test:** `tests/deep/test_dashboard_aggregator_naive_aware_adversarial.py`
- **Class:** naive-vs-aware datetime comparison (same class as QA-62/63/64/65; `content_scoring._score_recency` is the reference fix that normalizes naive -> UTC)

## Symptom

`DashboardAggregator.aggregate(index_instance=...)` computes dashboard stats.
`_compute_pages_per_day` (aggregator.py:79) builds a `dates` list by parsing
each page's `crawled_at` (a string) with `datetime.fromisoformat` or keeping an
existing `datetime`. The per-item parse is wrapped in
`except (ValueError, TypeError)` so a single bad item is skipped.

BUT the span computation at aggregator.py:93,

    span = (max(dates) - min(dates)).total_seconds()

lives OUTSIDE that try/except. When `dates` mixes a **naive** and an **aware**
datetime (both reachable: `CrawledPage.from_dict` parses a naive ISO string to
a naive datetime and an aware ISO string to an aware datetime), `max(dates)`
raises `TypeError: can't compare offset-naive and offset-aware datetimes`. No
`except` clause catches it, so the exception propagates out of `aggregate()`.

This is the same naive-vs-aware datetime seam class as:
  * QA-62 (content_archive.archive_old — VERIFIED, fixed in #1715)
  * QA-63 (sitemap.get_recent_entries + progress.elapsed_seconds — OPEN)
  * QA-64 (auth/api_keys.validate_key — OPEN)
  * QA-65 (search_facets range filters — OPEN)

The dashboard/aggregator.py `_compute_pages_per_day` site is a NEW,
previously-unfiled member of that class.

## Exact repro

    python3 -c "
    from personal_index.dashboard.aggregator import DashboardAggregator
    from personal_index.models import CrawledPage

    DashboardAggregator().aggregate(index_instance=I(), force_refresh=True)
    "

## Expected per docs

`_compute_pages_per_day` builds `dates` from each page's `crawled_at` and
computes a time span across them. A naive ISO string is a valid `crawled_at`
and parses successfully to a naive datetime. The span computation should
compare a naive datetime against an aware one the same way it compares two
aware values: normalize a naive datetime to UTC-aware
(e.g. `dt.replace(tzinfo=timezone.utc)` when `dt.tzinfo is None`) before
`max()`/`min()`/subtraction — exactly the reference fix in
`content_scoring._score_recency` (content_scoring.py:267-268). After the fix,
a mixed naive/aware `crawled_at` list should yield a finite `pages_per_day`
rather than raising.

## Asymmetry (same pages, only tz-awareness differs)

    mixed naive+aware crawled_at -> RAISES TypeError (defect)
    all aware crawled_at         -> computes pages_per_day (correct)
    all naive crawled_at         -> computes pages_per_day (correct)
